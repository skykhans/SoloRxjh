# 物品背包与经济采用合同

更新日期：2026-11-14。状态：**部分项目设计，未实现、未冻结**。官网系列与成长事实仍由[12数值目录](12-数值与物品目录.md)及其资料附录维护。本页给出本地容量、重量、交易和精确整数规则；不把项目容量/价格写成官网原值。三个容器、扩容价和仓储动作的结构化权威为[容器与仓储JSON](contracts/容器与仓储.v1.json)，下列相应表格是其阅读视图。

## 1. 定义与实例

正式物品分堆叠物和唯一实例。堆叠物包括药品、普通材料、成长材料、任务凭证、秘籍及功能消耗品；装备、披风和宝珠均为独立实例。1155款衣饰期限沿[唯一期限owner](contracts/衣饰期限.v1.json)逐ID分派；仓储、备用组、隐藏外观不暂停实例余时，整件到期与附加属性到期分别处理，完整衣饰类型/来源和到期授权尚未接入。[重量与权限owner](contracts/衣饰重量与权限.v1.json)明确1155款各500克、单件独占装备包/仓库槽，全部可本人仓储/确认主动丢弃、禁NPC卖/复购；1152款unbound可转让，3礼服character绑定。玩家交易仍待衣饰完整类型及计时适配器，不借首饰现有支持放行。同名、同强化或同外观不作为合并依据。

每个定义必须显式提供ID、类别、堆叠上限、单件重量、用途、获得途径、使用前置、绑定/出售/丢弃/仓储/加工权限及对应参数。禁止“缺字段即允许”或“未知类别即普通材料”。不支持的操作明确配置为禁止，禁止出售时卖价为不适用，不能把空价格解释为免费出售。

任务与消耗品已有[143条原始目录记录](reference/任务物品与消耗品目录.md)作为逐物品设计依据，尚不是正式定义。长白山参为重设技能点数道具，官网精确重设范围仍未载明；本地明确采用普通/升天气功共池洗点，见6.2，不归入生命/内力恢复品；同名任务物品按来源和用途映射，不自动合并成通用品。

[66普通首饰](66-普通首饰基础与贡献采用合同.md)已采用79款基础身份、逐件堆重权限及银娇龙取得事务，8普通原异常已明确本地采用，另9新版武勋由[70合同](70-新版武勋首饰成长与套装采用合同.md)独立采用；[67加工](67-普通首饰加工采用合同.md)及[68单实例结构](68-普通首饰实例与配置校验合同.md)已采用，完整档案/库存/收据日志schema和服务经济尚未闭合，不创建运行实例。

唯一实例保存定义ID、实例ID、真实成长状态和来源事件；实例只能归属一个容器或装备位置。血雨丸/青雨丸分别配置限制，宝珠和灵兽宝珠分别配置类型。全部披风目录保留男女/变体，不能将同名款合为一条默认外观。

堆叠合并要求定义、绑定、有效期及任务归属完全一致。每堆上限必须逐物品显式指定，允许范围1～9999；这个范围是项目配置校验界限，不是每种物品都能堆9999。装备与宝珠上限必须为1。

## 2. 容器与重量

以下均为项目容量方案，未作为官网事实：

| 容器 | 初始槽 | 扩容一次 | 最大槽 | 计重 |
| --- | --- | --- | --- | --- |
| 材料/消耗品背包 | 60 | 20 | 200 | 是 |
| 装备背包 | 40 | 20 | 200 | 是 |
| 角色私人仓库 | 100 | 50 | 500 | 否，仍保留物品重量定义 |

每堆占一槽，每实例占一槽。仓库按角色独立，不在同档案角色间共享物品。穿戴的两套装备和宝珠不占背包槽，但均计入携带重量；不能借备用组绕过负重。

重量使用非负整数“克”，角色初始负重上限100000克；不允许浮点千克比较。物品重量逐定义显式给出，允许明确为0的任务凭证，但未知重量不填0。负重不随职业/等级隐式增加；弓手千钧压驼的明确每有效级1000克加量见弓手气功合同，其他来源不得继承默认扩重。

拾取、购买、制作、取仓先检查最终携带重量≤上限及目标分区槽位；不足则整份拒绝。普通坏负重档仍拒绝，不能读档自动丢物。[弓手负重气功](contracts/弓手箭矢与距离气功.v1.json)明确合法源变化导致超重时，存先前合法容量→当前容量及事件/修订凭证，保物不补容量，禁止新增重量且仅行走，可存仓/卖/确认丢弃等减重；降回上限内清凭证。无合法来源凭证的超重仍是坏档，不用该例外修错数据。脱装备进包的重量保持不变，存仓才减少；临时预览不计重也不改变所有权。

扩容由仓管服务，材料包/装备包每次20槽费用分别为10万、50万、200万、500万、1000万、2000万、4000万两，初始容量不同导致可购买次数分别7次和8次：装备包第8次额外费用8000万两。仓库8次各增加50槽，费用依次50万、100万、200万、500万、1000万、2000万、4000万、8000万两。达到上限拒绝继续扣费；逐次费用是项目值。

## 3. 移动、整理与装备替换

移动使用源容器、实例/堆ID、数量、目标和修订号。先计算扣除源物后的最终布局、重量与归属，再一次提交；取消和失败不改变源。仓库禁止物、任务保护量和占用中的配方输入不能被批量移动绕过。

排序只改变排列，不改数量、ID、绑定、有效期或任务阶段。合堆先按稳定键排序再填充，不能把各堆上限相加溢出。拆分生成新堆ID，原堆减量；堆ID也不得与装备实例ID混用。

背包装备替换已穿装备时，旧装备占用源新装备腾出的同一槽；满包可以一换一。卸装须有对应背包空位。主辅切换只改生效组，不在背包间搬物，不改变负重；详见[13合同](13-装备组与宝珠采用合同.md)。

## 4. 货币与商店

银两、经验、历练及各类点数独立，以整数结算。新格式每字段范围0～9007199254740991，乘法、加法先验算不溢出；不使用浮点总价或32位上限。50亿两转职可正常支付，余额不足1两也拒绝，不能先扣到负数再修回。

每个可购买定义配置精确单价、库存规则及服务NPC；不存在的价格不是0。每个可出售定义显式配置卖价，禁止按买价自动乘固定折扣。批量交易数量须为正整数，预览总价与提交重新计算一致；报价过期拒绝，不按旧报价偷偷成交。至尊出售加成沿[至尊服务合同](contracts/至尊服务.v1.json)的npc_sale_effect：合法原逐单位卖价乘12000bp向下取整，再乘数量；未成交报价在到期/激活/续期改变权益来源或资格时失效，正式短事务先恢复再推进依赖计时，已成交记录不重定价。复购保原实际加成单价，不受当前权益影响。完整经济父仍待。

商业界面区分游戏自营官方商店与玩家市场。官方商店按各物品定义和NPC服务owner销售已授权的武器、装备、披风、消耗品等商品；逐项检查购买价格、资格、库存与服务位置，未授权的任务物、奖励或其他定义不得自动上架。UI可以聚合展示可访问的官方商品，但成交仍由真实服务和原经济事务处理，不使用现实货币，也不伪造成玩家挂单。

普通店库存项目方案为不限量，但仅对明确列出的商品生效；特殊书籍、活动/任务物品与独立装备需逐商品声明限购/库存，不能继承无限。单次订单最多9999件，按堆上限和空间拆堆；无真实批量空间则全部拒绝。

任务需保留的通用物品按当前保护量扣减可售数量。若请求超过可售数量则拒绝并提示，不静默减少成交数。唯一物品出售只扣指定实例，不随显示名批量删除。

## 5. NPC复购

V25复购类别和加工限制须逐定义核对；本项目先明确会话规则：每角色最近20条合格出售记录，按出售顺序保留，21条移除最旧一条；离开当前商店关闭面板保留，退出角色会话清空。此容量/清理方案是项目设计，不能声称是官网精确列表规则。

复购同一笔出售的原实例或原堆状态，价款等于该笔实际收到银两；部分复购堆叠物按原单价结算。售出记录中的物品不属于背包或仓库，不贡献属性或重量，不得作为制作输入。复购成功后减少记录剩余数量，实例复购后移除记录，不能同时保留可重复购买副本。

检查当前容量、重量及余额；失败保留记录。哪些加工/类别允许复购仍需全物品定义闭合，未知条目禁止进入正式商店配置，而不是运行时默许或默禁。旧程序“出售即永久不可恢复”不作为新功能合同。

### 5.1 保管、部分复购与退出恢复

[NPC复购JSON](contracts/NPC复购.v1.json)是本地保管协议权威，[记录schema](contracts/NPC复购记录.schema.json)仅校验五字段引用条目。每条记录保存原出售收据、原NPC、种类、保管ID和精确单价；剩余数量只在保管正文中保存，原出售数量/入账不改写。是否允许具体物品及加工状态复购仍由逐定义权限决定，本协议不新增可复购物。

角色会话的buyback_stacks/buyback_instances独立保管正文，不在character当前持有注册表，不计重/属性。每保管正文恰有一记录。所有商人合计最近20笔，部分复购不刷新顺序；只能在原售出NPC有效服务内复购本人记录。关商店、换地图只使服务报价失效，记录保留；角色会话退出、FIFO淘汰才清剩余量。每角色会话新建空记录及两空保管表，不能借切商店重置20笔限制。

| 操作 | 数量及来源处理 |
| --- | --- |
| 整堆出售、整堆原样取回 | 原ID/修订/来源跨持有与保管域移动，记正式域迁移收据，不造数量流 |
| 部分出售 | 消费完整旧版本，输出原ID新修订余量及新ID保管堆；两输出数量守恒 |
| 部分复购或返回合堆 | 消费保管完整版本及被改目标堆版本，输出保管余量/现持结果并保全部贡献；不铸造新购物 |
| 实例出售与复购 | 原完整实例移域，保成长/耐久/ID，不触发玩家转让归0；合法性逐类型核验 |
| 淘汰或结束 | 仅终结剩余保管实物；堆记buyback_cleanup，实例记完整终结收据；不退售款、不动已返还物 |

每真实源堆/实例形成一笔记录。批量出售先计算完整FIFO结果，超20笔同笔终结最早记录，售款仍按完整合法订单支付；失败不减少订单或部分执行。复购按请求数量乘原实际单价扣随身钱，先重查原NPC、角色修订、空间与负重，失败保原状态。全部钱、正文、位置、记录、来源和修订同笔提交，重试复用原结果。

复购队列不写持久角色快照，正式售出/域迁移/数量变化/结束收据须保存完整保管证据，直到会话关闭决定已持久。正常退出先持久清剩余量及结束决定；强退重开由原会话权威按已提交收据推导原会话余量，并用同一确定结束ID清理；LAN客户端须取得原房主结束结果，保存并清玩法会话守卫后才进入新玩法，不重开上次复购权利、不补背包/退售款。清理ID为buyback-close:加71确定JSON数组[character_id,session_id]的SHA256。未知来源/结果不确定明确报错，不能删记录猜完成。

LAN断开而房主仍保留角色时不等于结束会话；结束和复购结果遵守房主唯一决定及19连续序号，不由客户端另造退款。完整域迁移/实例终结收据、会话ID分配、逐物品资格和实际异常退出/LAN验证仍待。本段为采用设计，不是已实现功能。
