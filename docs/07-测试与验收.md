# 测试与验收

更新日期：2026-11-13。本页定义目标版测试门槛，实际结果集中于[实施与验证记录](09-实施与验证记录.md)。计划用例、旧Rust历史结果、Godot自动化、原生图像和人工操作分别记状态。

## 1. 验证层次与顺序

先通过文档D0，再按P阶段实现程序及必要自检；程序完成后执行T系统功能测试，T通过后实施A美术/现代界面，再执行最终渲染、性能和发行回归。参考来源、功能、数值、数据与验收要互相可追溯。

| 层次 | 方法 | 能证明的范围 |
| --- | --- | --- |
| 文档 | 本地链接、UTF-8、表格/围栏、系统覆盖和版本/状态一致性 | 文档合同完整，不证明程序可用 |
| 静态/导入 | 精确4.7.2检查、无窗口导入、GDScript解析与资源引用 | 工程和脚本可加载，不证明游戏通关 |
| 规则 | 无渲染、固定时间/种子、隔离数据 | 数值、前置、事务、AI、随机边界与存档 |
| 场景集成 | 正式场景、内部输入/控件路径、固定步推进 | 生命周期、UI授权、暂停、世界/存档联动 |
| 原生图像 | 正式渲染、固定分辨率、实际查看图像与动画序列 | 布局、中文、模型、姿势、材质与反馈 |
| 发行 | Windows release、独立目录、离线、保存重启 | 包完整性、路径、功能和进程退出 |
| 人工/设备 | 真实键鼠、IME、播放设备与参考硬件 | 不能由前述测试替代的实际体验 |

测试覆盖风险和边界，不为常量、简单访问器或与实现重复的代码制造无效测试。随机边界使用固定种子，动作和刷新使用模拟时间。

## 4. 美术与现代界面验收

在1280×720、1600×900、1920×1080、2560×1440分别检查登录、创建、选角、HUD、主/辅助装备与宝珠/披风、背包/仓库、武学/气功、商店/铁匠、任务/门派、地图/消息、设置及确认页。覆盖长姓名、长物品说明、空/满列表、禁用、错误、IME组合和缩放。

全部职业的武器持握、普攻与四技能、远程轨迹、敌人预警、命中、死亡、披风运动和切换需要实际渲染。动画检查至少含起手、命中、收招及连续过程，不用单帧姿势代替动作验收。旧剑气侧弯、穿云刺朝地列为明确回归项。

截图必须记录引擎/后端/分辨率并实际查看；程序PASS不能代替视觉结论。没有查看的截图保留“未查看”，不能根据文件存在判为通过。

## 5. 性能与稳定性

参考环境：Windows10/11 x64、四核八线程CPU、16GB内存、GTX1650 4GB或同级、SSD、1600×900。该配置是验收基线，尚不等于实测最低配置。

| 指标 | 门槛 |
| --- | --- |
| 常规探索 | 平均≥60FPS |
| 战斗压测 | 8普通敌人与必要特效，平均≥50FPS，P95帧耗时≤25ms |
| 冷启动进入世界 | 本地SSD≤15秒，记录缓存/冷启动条件 |
| 进程工作集 | 稳定探索≤1.5GB |
| 会话泄漏 | 10次往返后世界节点清零，第10次菜单较第2次工作集增长≤100MB |
| 稳定性 | 连续探索/战斗30分钟，无崩溃、卡死、存档或任务阻断 |

使用release导出，记录CPU/GPU/驱动、引擎、后端、分辨率、垂直同步和采样场景。性能样本至少60秒；在其他显卡测到的结果不能宣称参考GTX1650通过。禁止使用旧文档中的推测FPS或Debug/Release倍数当成实测。

## 6. 故障与发行阻塞

配置/脚本/资源必需检查失败、崩溃/卡死、任务无法完成、边界穿越、奖励复制、实例丢失、失败保存破坏旧档、主要控件不可达、中文缺字、危险提示不可读或未关闭本次验证进程，都阻止对应阶段通过。

缺少正式美术、未修的武器/技能姿势、未实现的职业或高阶转职或仅展示静态文本的面板不能作为完整系统交付。不得通过删除旧档、强制截断字段、跳过坏实例或换占位资源消除失败。

| 两名接收者仅一人已确认 | 整笔结果仍可恢复，未确认项不被压缩删除 |
| 客户端离线改档形成分支 | 明确冲突，不按时间戳合并或静默覆盖 |
| 断线9.9/10/119.9/120秒 | 实体受击/移除、活动退出与队伍席位按边界分别执行，重连不回血 |
