# 数据与存档

更新日期：2026-11-15。本文定义Godot目标数据合同。项目没有数据库，不建立、连接或修改数据库；所有游戏数据均为随包配置与本地文件。

## 1. 数据分层

| 分类 | 内容 | 持久化方式 |
| --- | --- | --- |
| 正式配置 | 地图、职业、成长、武学、装备/披风、物品、配方、任务、怪物、掉落、NPC服务和资源清单 | `res://assets/config/*.json`，只读 |
| 本地档案 | 档案ID/名称、角色列表、档案设置 | 每档案一个JSON文件，一次提交 |
| 角色进度 | 身份/职业/外观、成长、货币、装备、背包/仓库、技能、任务、门派、随机序列、位置 | 档案内独立角色快照 |
| 普通战斗现场 | 未要求完整世界快照的故事普通敌人短期生命/AI、掉落、竹命中/刷新、投射物、路径 | 不写角色存档，重建现场；不适用于修炼共享世界或活动战斗 |
| 修炼共享世界 | 世界时钟、432刷点生命周期、活体怪物战斗快照及死亡/授予结算 | 房主档案内世界快照，独立于各角色快照；同一房间不因玩家切换重建 |
| 角色计时与活动 | 角色冷却/效果剩余时间、装备切换剩余时长、活动引用及结算ID | 按各活动owner唯一持有；六转私场完整战斗快照在房主world，角色仅持引用；离线不推进，恢复不重抽或刷新 |
| 会话界面 | 消息、草稿、筛选、地图路标、预览、未确认数量与操作 | 不持久化，退出清理 |

角色、装备、物品、职业、地图、NPC、配方与任务均使用稳定ID，展示名可调整。节点路径、ObjectID、Resource句柄、动画播放器和内存地址不能写入存档。

## 2. 配置与严格校验

| 配置 | 职责 |
| --- | --- |
| world / exploration | 地图对象、区域、出生点、安全区、连续碰撞、镜头和移动 |
| classes / skills | 完整职业体系、武器条件、主动武功、被动气功、晋级与路线 |
| items / equipment | 堆叠物、唯一装备定义、槽位、披风、属性、操作限制和商店价格 |
| crafting / upgrades | 强化概率/费用、合成孔、石头适配、洗炼、转移和制造配方 |
| gameplay / quests | 成长、战斗、怪物AI、掉落组、任务与门派规则 |
| assets | 正式场景、模型、材质、骨骼/命名动画、字体、音频与许可引用 |

按实际职责组织JSON，避免同一数值出现在多个正式文件。旧RON一次性转换并逐字段对照；新增系统完成后不维护两份正式配置。

拒绝未知/缺失字段、类型错误、重复ID、非法枚举、非有限值、越界、负数、经验阈值乱序、概率和权重非法、时序矛盾、资源越界路径、无效引用、出生点碰撞、无效掉落和配方环。错误给出文件、字段路径与原因。

JSON数字解码后必须验证整数性与范围，不能用 `int()` 截断非法小数。旧格式无符号字段仍按0～4294967295校验；新schema5经济字段使用64位整数，并限制在JSON可精确表达的0～9007199254740991，必须覆盖官网50亿银两等需求，不能沿用32位上限导致高阶转职无法完成。随机seed用固定64字符小写hex字符串表达，next_block为安全整数计数；算法使用SHA-256和53位拒绝抽样，不把64位随机状态写成JSON浮点。

## 3. 档案目录与提交单位

Windows默认根目录为 `%LOCALAPPDATA%/SoloRxjh/`。新档案文件为 `profiles/<profile_id>.json`，文件名与内部ID必须一致。通过枚举档案文件展示本地列表，不另存一份容易失配的角色索引。

每档案最多6角色，角色快照、外观和设置置于同一个档案文件；一个角色保存时复制档案、更新该角色、完整校验再提交。这样创建、删除和选择记录不跨多个文件产生半份状态。角色间背包、仓库、货币和随机序列不共享。

`--save-dir PATH`覆盖整个存档根目录，测试必须显式指定隔离目录。缺失LOCALAPPDATA时明确报错，不能猜测其他位置。未知档案、损坏JSON或不兼容版本显示原因，不自动重置、删除或读入临时文件。

### 完整角色根的组装与联合校验

上述字段表是完整角色根的登记依据，仍须与全部任务/活动/配置owner闭合后建立严格根schema。原容器、资源、快捷栏、生命与效果联合schema是验证投影，不是持久包装：角色内不新增resource、locations、quickbar、life_projection等镜像对象，identity.class_id也不复制到角色顶层。技能/气功/效果等已有真实子根仍保原嵌套层级。

组装时先对完整原角色运行根白名单、字段必填及原子组件校验，再从同一份已验证正文提取各联合投影；class_id仅从identity取得。不能把若干additionalProperties=false的严格投影直接allOf到完整角色上，否则每个投影都会把其他合法角色字段误判为未知。根属性复用原单字段/子根定义，跨字段规则沿原联合校验单独运行，不复制出第二套取值范围。

同一快照依次验证：身份/安全整数与UTC、原进度/生命/职业资源、完整技能/气功及冷却/效果联合约束、正文注册表与所有正式位置双向覆盖、任务/活动/配置及来源授权、会话/交易/网络链与档案全部原日志/计数器覆盖。前一步失败不继续据局部字段重建可用角色。原头不存在、位置悬空、未知当前资源族或原任务owner未闭合均是失败，不能补空、删字段或借投影隐藏。

保存候选需同时验完整档案及被改角色，并按该原事件的允许差异验证前后状态；历史日志校验读取原提交输入/结果，不能要求当前角色仍等旧初始状态或旧修订。全档案保存不等于全角色业务修订都加一，未改角色必须保原正文与修订。当前缺完整任务/活动/配置与世界根，以上组装规则不构成D1完成或可运行声明。

元数据只从完整已验证profile提取schema_version/content_version/profile_id/profile_name/revision/selected_character_id/settings七字段运行[投影](contracts/档案元数据投影.schema.json)，不保存metadata包装或把该投影当完整档案。选中ID必须命中同档真实角色；设置保存用最新完整档案，只改settings与档案修订，未决写事务阻止时只保进程草稿，不能覆盖业务日志。

装备实例包含唯一ID、定义ID、类型化成长数据与来源。普通装备的强化/合成、进化/提真/武勋等分开；宝珠保存自身品质，不把一个随机稀有度倍率用于所有武器防具。各类型所需字段必须明确校验，不增加无用途字段或缺值补普通。披风引用已解锁外观/显隐，预览不写正式装备。实例ID不可复用，同名装备不因排序合并。

[68普通首饰实例](68-普通首饰实例与配置校验合同.md)明确79款单实例九字段完整白名单、创建/加工/配置来源及严格数字token。位置仅由外层容器持有；该单实例schema不替代完整档案、收据日志和库存唯一性/预算校验，缺字段或未知根字段不能投影隐藏。

所有权、主动装备条件、当前生效条件分开。官网明确宝珠在隔体传功后保留原角色而暂时失效，资格恢复后重新有效；该合法状态不能静默删物或一概拒绝读取。主动穿戴仍检查140级/四式等条件，未知定义、错误槽位、重复实例和未声明状态不能借此放行。主/辅助切换不得复制装备、刷新技能冷却或把两组属性同时生效。

等级、最大生命、最终攻击防御、护体后伤害、气功有效等级、任务门开关及已击败首领由持久进度推导，不能存两份相互矛盾的值。14职业核心/次级属性以[基础成长合同](14-职业创建与成长采用合同.md#21-基础属性与成长采用值)按经验等级和实际晋级重算；迟做一式的基础属性补齐不保存另一份可重复发放的奖励。当前生命/内力/体力独立保存，升级提高上限不自动填满。角色八字段另按[资源联合schema](contracts/角色资源联合.schema.json)验证：生命/职业规则复用，死亡清怒气及相应职业临时资源，满体力清恢复余数；完整角色先验白名单再取投影，不借投影丢弃未知字段。

累计经验语义范围为0～[14经验合同](14-职业创建与成长采用合同.md#43-等级经验与跨级满级结算)的180级阈值，不以通用JSON整数上限放行超满级坏档；不保存隐式溢出经验银行。经验结算结果分别记录原分配、实际入账与满级溢出，网络重放复用同一结果；不能在客户端按本地另一条曲线重算。

反气功等级预算与十二转开放由经验/晋级推导，见[14点数合同](14-职业创建与成长采用合同.md#41-反气功等级点数与解锁)。持久化技能ID/投入、合法道具来源及剩余时长和明确配置覆盖，不另存可重复领取的等级赠点余额或生效装备预算。换装导致超预算时的分配清空与装备变更同笔保存；合法失效与非法超预算快照分别处理，未知技能、负投入、伪造道具来源不能自动修正。

U33允许角色自定义覆盖：等级仍由经验推导，最大生命/最终攻防等先计算规则值再应用明确覆盖；覆盖不是另一份派生缓存，清除时重新计算。配置中心直接修改实际物品/任务/资源进度，并记录配置来源，不产生第二份角色数据。正常玩法合法状态与用户配置例外显式区分；未知定义、重复实例、非法JSON仍拒绝。

### 4.1 计时与活动快照

世界时间使用60Hz整数步，持续2小时为432000步、20分钟为72000步、眩晕10秒为600步。剩余步数须为非负整数且不超过对应规则上限；角色效果包含定义ID、来源事件、层数及必要触发状态，不保存可失配的最终属性加成。装备组冷却保存剩余整数毫秒0～1000；离线冻结，不保存系统单调时钟绝对值。

允许重建的故事普通敌人现场重建不清除角色冷却、负面状态或成功BUFF；死亡、解除或技能明确改变效果时按对应规则执行。角色未完成动作跨保存需要保存动作ID、剩余阶段、已扣资源及已命中集合，或只在动作结束后捕获保存；不得保存已扣费却遗漏待结算动作。正式实现选择“动作及其全部派生事件结束后捕获”，活动战斗及修炼共享世界快照除外。连击追加/箭矢延迟队列与回避一次增幅按[连击合同](contracts/连击与回避追击.v1.json)记录，不能只等动画结束漏存已付资源的延迟伤害。

进行中讨伐必须在固定步边界保存逻辑快照：玩家和9名伙伴及敌人的稳定实体ID、位置/朝向、生命/资源、动作阶段/剩余步、冷却/效果、仇恨/目标；召唤物、未结算投射物及命中集合；安全罩/红区/人数圈/四珠状态、阶段进度、弱点计数、时限和随机消费位置。特殊资源快照包含动作级愤怒点消费/充能已发/和弦随机已判标记，不能仅靠目标命中集合推断资源是否已结算。只记录存在的逻辑状态，不保存NodePath或引擎句柄。

活动保存不退回阶段开场，不重置敌我生命、已消费道具、机制进度或随机序列。恢复先验证全部定义/实体引用和阶段一致性，再重建表现；失败明确报错，不清空活动继续玩。胜利或失败提交时移除活动现场快照，保留尝试与奖励结算记录；退出后不额外重新生成同次掉落。

角色手动保存、暂停退出和自动保存均捕获同一一致状态；活动战斗中允许快照，普通未完成动作则等到动作结束再捕获。若无法取得一致状态，显示尚未保存，不提前写“保存成功”。这些是待实现合同，必须实测持续伤害、飞行投射物、濒死及机制倒计时的保存往返。

旧故事/区域/冒险/门派保留组件使用[严格子结构Schema](contracts/故事冒险门派进度.schema.json)与[映射/投影合同](contracts/故事冒险门派进度.v1.json)，置于`character.quests.retained_story_adventure`，不是完整schema5。该组件是旧主线/区域/冒险/门派字段的唯一持久来源，character.progress不复制这些字段。Q001～Q005通用任务面板通过明确适配读story_stage/journey.stage，不另存重复交付/首领/门状态。

主线未完成时journey必须是旧默认；区域猎物5只前后与首领/回报阶段一致，北方预累计与两重复轮次仍按原规则。门派晋升要满足原等级/主线/区域双前置，重复轮次不能超过对应击杀/采倒数；一次工棚已领标记缺对应3/3/6计数也须拒绝。旧导入不因缺逐次奖励日志补发物资或伪造一套事件历史；新事务凭证只管去重，不成为第二任务状态。

### 5.1 导入凭证与删除记录

[凭证JSON Schema](contracts/旧档导入凭证.schema.json)定义v1必填/类型/枚举/ID格式和拒绝未知字段；[导入合同](contracts/旧档导入.v1.json)的receipt_policy维护语义校验，结构通过不代表来源关系正确。每笔以目标档案ID+原字节摘要+导入档ID唯一，保存来源schema/content、目标角色ID、转换数值、四剑技原等级、原装备路径/定义/等级到目标实例ID、导入时档案修订，并将正式结算身份、原银两/背包堆快照和三种钱物来源流纳入同一凭证。无本机绝对路径或外部数据库索引。

四版本由schema直接要求精确配对，语义仍须核真实源字节对应版本。体力源词元必须完整匹配JSON数字并按有理数解析，禁止eval/容错解析；源级别/上限、目标经验/HP比例、技能等级及实例路径/摘要交叉核对。凭证历史按固定导入档v1验证，目标初始上限133+7×(旧等级−1)，不能因角色后来配置/升级而用当前上限否定旧凭证或重做换算。

present要求当前恰有该角色；明确删除角色时同事务把凭证改deleted，角色ID不再存在。保留摘要/映射用于防重，同源再次导入只提示先前已导入后删除，不复活、不补包；重新建立副本必须是另行明确设计的克隆操作，当前导入不隐式承担。除该删除标记外凭证不可被普通玩法重写。

实例映射指首次导入归属，不要求该实例永远留在初始槽，之后合法移动/出售/消耗不会令凭证失效，更不能补回已消费物品。原路径必须唯一，按已规范化旧结构标识，不能拿当前容器序号重建ID。导入修订不得晚于当前档案修订；坏摘要/字段/重复来源/矛盾删除引用拒绝，不通过扫描角色猜一个修复凭证。

这只闭合导入凭证，完整schema5各系统字段、旧故事/门派到正式定义映射仍需总检；目前没有导入程序或用户存档实测。

[死亡与复活保存合同](contracts/死亡与复活保存.v1.json)明确新档两个生命状态。死亡/活动失败/已消费物品及唯一凭证同笔提交，保存退出或读档不再结失败/补血；旧1～4源0HP仍拒绝。普通复活先验工棚锚，修炼房按已保存条件和显式选择检验原死亡位置或泫勃返回锚，再原子切active并恢复实际资源/清待死，保技能药物冷却，不发初始包；坏锚/位置保待复活不选替代位置。死亡取消动作后应能捕获终局，不能被“等动画和后代完成”卡死保存；已合法独立状态与取消未发攻击的区别按源规则保留。

## 6. 保存流程与故障要求

1. 固定步事务完成后捕获一致快照；死亡按明确awaiting_respawn/0生命及结算记录保存，不能延迟到回城或写成active。
2. 复制档案，替换当前角色，完整验证所有角色、实例、设置与引用。
3. 目标文件同目录写唯一临时文件，拒绝占用已有临时文件；写入后flush并关闭。
4. 通过DirAccess在同文件系统提交替换，只有成功才更新“已保存”。不先删除旧档。
5. 失败保留旧文件和当前内存进度，显示路径/原因，清理本次创建的临时文件；旧临时文件不自动覆盖或当作有效存档。

FileAccess/DirAccess替换已有文件、权限拒绝、异常中断、磁盘写入失败和旧文件保留都必须在Godot4.7.2/Windows下实测。不能沿用Rust版ReplaceFileW的通过结论，也不能在失败时改成删除旧档再写。

成功事务触发自动保存；完整共同发布与失败判定唯一归[档案共同提交](contracts/档案共同提交.v1.json)。失败保存保留同一次完整内存候选并显示“未保存”，暂停依赖该候选的固定步、资源业务和会话结束；只允许保存重试或无写查看，不重算奖励/随机、不继续消费未落盘奖励。保存成功必须锁内重读正式文件确认完整候选，之后才发布网络结果或发送真实保存ACK。替换存疑先核正式文件精确before/after，不凭修订号、单条凭证或当前缺包猜成功；进程重开只按完整合法正式档案及原决定恢复。

## 7. 事务与测试隔离

### 7.1 局域网与多开补充

同一档案文件仅一个实例持有写锁；不禁止不同档案/独立根的多开。锁获取失败不偷偷改路径或复制存档，异常锁按实际进程与系统文件锁判断。[19联机合同](19-局域网组队聊天与多开.md)要求客户端只保存自身角色、房主保存世界和持久结算日志：房主世界按本文既有唯一归属保存在房主档案的`worlds[world_id]`，同档案完整替换；包含协议/规则版本、参与角色修订、活动/队伍状态及待确认/已确认结算ID，不另写一份独立worlds文件维护同一权威世界。

网络命令去重使用`world_id + character_id + settlement_id`，不使用会重分配的Peer ID作为持久身份。房主日志持久成功后才发结果，客户端应用/存档成功后确认；重连只重放未确认结果，客户端持久去重。跨文件/跨机器未确认状态须明确展示，不宣称全体同时原子保存。房主失败不发已提交结果，客户端失败不重抽或重复扣票。

每笔记录包含世界序号、请求ID、规则版本、前置世界修订号、随机前/后状态和全部参与者结果。各参与者保存角色ID、结算序号、前/后修订号、变更及校验后的结果快照、确认状态。多人经验、门票或掉落一次业务提交写入同一房主文件，不能先通知一人成功、再因另一人写入失败回滚半笔。

房主流程为校验→在副本计算世界/角色/随机结果→持久写入新世界快照与待确认日志→发布内存结果和网络消息。日志写失败整笔不提交，保持原随机状态；成功后崩溃则按日志恢复，不再次计算随机。房主自己的角色也作为接收者应用结果并确认；世界与本人角色同档时每次写入均复制最新完整档案以保留协议守卫和其他字段，不把同档替换误当远端各档案同时原子。

客户端收到结算时要求前修订号等于当前已提交修订，按序应用结果和`network_receipts`到同一档案快照后确认；保存失败保留待保存内存，暂禁该角色新的经济/任务/配置事务，不阻止其他玩家。重发同笔只重试保存/确认；序号缺口请求缺失结果，不跳过。不能把重复结果当重新获得的经验/物品。

`character.network_receipts`按world_id保存最后连续应用序号及角色结果修订；房主按角色保存连续确认水位。全部接收者确认与世界新快照持久仅是未来压缩的必要条件；当前没有已采用的完整压缩证明协议，原world日志与接收来源证明全部保留，不裁剪前缀。旧序号重试只回复已提交状态或同步快照，不重新发奖。未确认事件不按天数或条数自动丢弃；空间不足明确停止新业务并提示，不删除记录继续游戏。

重连先比对世界ID、角色ID、协议/规则哈希、接收水位及前置修订。客户端离线另改角色或导入造成分支时拒绝直接合并，并显示两边修订；用户可先导出本地分支，再明确选择恢复原房主分支；退出后继续本地玩法仍须原权威会话结束、全部结果补齐并持久清guard，存在未决不得以分支选择绕过。禁止按时间戳自动选择、覆盖或把差额再次结算。手动回滚/篡改本地文件不在防作弊承诺内，正常保存链的重试去重必须保证。

聊天记录不持久化，房间口令不写角色/配置方案；房主结束世界保留必要结算记录。当前不执行日志压缩/裁剪，连续确认水位仅按原ACK协议推进；断线角色的10秒实体/120秒席位规则见19合同；普通角色单机文件规则继续有效，数据库始终不使用。以上字段均为计划结构，Windows替换故障与多进程实际实现仍未验证。

容器槽数、重量整数克、扩容等级/费用及复购会话规则见[17物品合同](17-物品背包与经济采用合同.md)。重量和容量由物品与扩容进度推导，复购队列不写持久角色快照，售出/域迁移/数量变化/结束正式收据须保完整保管证据；原会话未结束时重开先持久唯一清理再进入玩法，按17及NPC复购JSON执行。不得把已售出实例同时计入背包。全部逐物品定义尚未闭合，本方案未实现。

创建/删除角色、换装、扩容、仓储、批量交易、拾取、强化、合成、转移、制造、学习/洗点、任务与门派都检查完整前置后一次提交。随机结果和相应资源变更属于同一个结果，重复请求不重新抽取。

### 角色删除的决定边界

删除仅由档案菜单针对明确角色ID发起。确认面板显示从当前已验证角色读取的姓名、职业、等级及背包/仓库/装备和银两永久失去的后果，输入当前完整姓名后确认；列表排序、选中项变化和重名显示不能替换已确认目标。确认时冻结目标ID与预期档案/角色/库存修订，持档案锁重新读取最新完整正式档案；任一修订或姓名不符要求重新显示目标并确认，不能自动切到相邻角色。预留前取消不写日志、不消耗编号。

删除是全档案排他事务。开始前必须已退出该档案所有活动玩法并收束原会话/交易/活动退出及保管结束；未决导入、创建、资源业务、客户端待保存结果或房主未确认接收者任一存在时拒绝删除。远端权威不可达时保留原守卫，不能按进程结束或席位释放视作已结清。只读历史begin或已完成结果的存在本身不阻止删除，但其引用闭包必须完整。

正式删除决定须沿通用结算身份分配及请求去重，保留目标ID、确认时的原身份/修订、冻结计划及唯一终态。请求重试先定位原决定，再检查当前目标存在性；已提交只返回已删除结果，已取消只返回原取消。目标缺失而无合法原删除决定应拒绝完整状态，不能现场补一条成功删除或把旧导入凭证自动改为deleted。严格命令、计划、三阶段事件及原三流专用删除分支见`contracts/角色删除.v1.json`与`contracts/角色删除事件.schema.json`；完整根与真实来源闭合前不得运行删除。

提交在一次完整档案替换中移除恰一个目标角色、持久唯一删除决定、推进档案修订，并将该角色对应旧导入凭证从present改为deleted。其余原凭证字段/流/源字节不变，创建事件和全部历史请求/会话begin/来源依赖仍保留。若selected_character_id等于删除目标，同笔设null；否则保原值，删除最后一个角色允许空列表/null，不自动创建或选择另一个角色。worlds及其他角色不随角色删除连带移除。

钱物不能因角色正文消失而转成全局可领取余额、掉落、邮件或他人仓库。提交须由同一删除决定终结目标当前全部背包/仓库/装备/宝珠/保管外的合法资源位置与银两来源头，完整来源图能区分已转给他人的后继与删除时仍归目标的资源；前者保现持有人，后者不能再消费。历史输出继续证明曾经发放，不重新激活成当前持有。消费/退役/银两流仅由原删除事件committed授权character_deletion；不能冒用discard、configuration_remove或configuration_decrease。严格分支已接入，全量覆盖、来源头终结与完整根验证仍为运行前置。

预留与决定写盘存疑均冻结该档案后续写入，重读同正式文件并全量验证：仍为原预留则按冻结计划恢复，已提交只回原结果，已取消只回取消。角色已移除而决定未提交、凭证deleted但角色仍在、选中ID悬空或资源只终结一部分均拒绝，不能拼接内存/备份/临时文件修补。明确取消只在原协议允许的预留阶段持久终态，不回收编号、不改角色/资源；规则包或证据缺失保留待恢复，不用取消掩盖损坏。

角色删除不删除档案文件、不释放档案数量，也不重置任何分配计数器。整档案创建/改名/删除的目录锁与多文件协议单独设计；不能用删除某角色的授权执行目录或档案文件删除。


测试只写 `target/verification/` 下独立根目录，生成档案和旧档样本，验证后清理。用户实际存档不进入测试；本任务不读取或修改用户LOCALAPPDATA中的游戏进度。

修炼BUFF保存采用修炼之门合同`timed_buffs.persistence`：世界必存`world.training_gate_clock_steps`，显式新世界为0；角色必存`training_gate_buffs.by_world`，新建与已知旧档转换显式为空。每世界存`observed_world_step`与四主题的`last_claimed_cycle_or_null`、`remaining_world_steps`，不冗余保存绝对到期值。重连用权威世界步差扣时，时钟倒退或新格式缺字段拒绝；整世界离线冻结。死亡保留领取账本与时长，失活期间仍按世界步扣时。

修炼每日任务保存`character.training_gate_daily.by_world`，新角色与已知旧1～4转换显式空账本；每世界存观察步与八任务状态、接取日或null、最近交付日或null，绑定物品保存角色/世界/任务/日来源。任务无独立收集数量缓存。载入验证状态/实物/收据一致、世界时钟不倒退，先处理5184000步日界过期再接收动作；新格式缺字段拒绝。

修炼怪物状态由修炼怪物与刷点JSON维护，世界保存432稳定槽及普通generation/复活等待或召唤周期状态、生命/位置/朝向/观察步，并保存战斗动作/冷却/状态及唯一死亡收据。重载不回血，召唤过期移除不产生击杀；新格式缺槽拒绝，已知旧档仅显式新世界创建初始化。

便携回城按便携传送与修炼限制合同保存已接受动作ID、真实堆引用预留、源地图/位置、剩余0～180步和同组剩余冷却；只有一次实物所有权。恢复严格验证物品/动作/世界与源目标规则，禁止重载立即完成或刷新读条；成功扣1/移动/冷却/收据同事务。
