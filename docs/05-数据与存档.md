# 数据与存档

更新日期：2026-11-14。本文定义Godot目标数据合同。项目没有数据库，不建立、连接或修改数据库；所有游戏数据均为随包配置与本地文件。

## 1. 数据分层

| 分类 | 内容 | 持久化方式 |
| --- | --- | --- |
| 正式配置 | 地图、职业、成长、武学、装备/披风、物品、配方、任务、怪物、掉落、NPC服务和资源清单 | `res://assets/config/*.json`，只读 |
| 本地档案 | 档案ID/名称、角色列表、档案设置 | 每档案一个JSON文件，一次提交 |
| 角色进度 | 身份/职业/外观、成长、货币、装备、背包/仓库、技能、任务、门派、随机序列、位置 | 档案内独立角色快照 |
| 普通战斗现场 | 普通敌人短期生命/AI、掉落、竹命中/刷新、投射物、路径 | 不写角色存档，重建现场；角色计时与活动快照另存 |
| 角色计时与活动 | 角色冷却/效果剩余时间、装备切换剩余时长、进行中活动逻辑快照与结算ID | 写入角色；离线不推进，恢复不重抽或刷新 |
| 会话界面 | 消息、草稿、筛选、地图路标、预览、未确认数量与操作 | 不持久化，退出清理 |

角色、装备、物品、职业、地图、NPC、配方与任务均使用稳定ID，展示名可调整。节点路径、ObjectID、Resource句柄、动画播放器和内存地址不能写入存档。

## 2. 配置与严格校验

| 配置 | 职责 |
| --- | --- |
| world / exploration | 地图对象、区域、出生点、安全区、连续碰撞、镜头和移动 |
| classes / skills | 完整职业体系、武器条件、主动武功、被动气功、晋级与路线 |
| items / equipment | 堆叠物、唯一装备定义、槽位、披风、属性、操作限制和商店价格 |
| crafting / upgrades | 强化概率/费用、合成孔、石头适配、洗炼、转移和制造配方 |
| gameplay / quests | 成长、战斗、怪物AI、掉落组、任务与门派规则 |
| assets | 正式场景、模型、材质、骨骼/命名动画、字体、音频与许可引用 |

按实际职责组织JSON，避免同一数值出现在多个正式文件。旧RON一次性转换并逐字段对照；新增系统完成后不维护两份正式配置。

拒绝未知/缺失字段、类型错误、重复ID、非法枚举、非有限值、越界、负数、经验阈值乱序、概率和权重非法、时序矛盾、资源越界路径、无效引用、出生点碰撞、无效掉落和配方环。错误给出文件、字段路径与原因。

JSON数字解码后必须验证整数性与范围，不能用 `int()` 截断非法小数。旧格式无符号字段仍按0～4294967295校验；新schema5经济字段使用64位整数，并限制在JSON可精确表达的0～9007199254740991，必须覆盖官网50亿银两等需求，不能沿用32位上限导致高阶转职无法完成。随机状态用固定格式字符串表达，避免JSON浮点精度丢失64位状态。

## 3. 档案目录与提交单位

Windows默认根目录为 `%LOCALAPPDATA%/SoloRxjh/`。新档案文件为 `profiles/<profile_id>.json`，文件名与内部ID必须一致。通过枚举档案文件展示本地列表，不另存一份容易失配的角色索引。

每档案最多6角色，角色快照、外观和设置置于同一个档案文件；一个角色保存时复制档案、更新该角色、完整校验再提交。这样创建、删除和选择记录不跨多个文件产生半份状态。角色间背包、仓库、货币和随机序列不共享。

`--save-dir PATH`覆盖整个存档根目录，测试必须显式指定隔离目录。缺失LOCALAPPDATA时明确报错，不能猜测其他位置。未知档案、损坏JSON或不兼容版本显示原因，不自动重置、删除或读入临时文件。

## 4. 新格式

目标档案格式为 `schema_version=5`、`content_version=jianghu-godot-1`。这是新增多角色/职业/装备结构导致的版本变化，不因引擎名称变化随意改旧档版本。

| 字段 | 约束 |
| --- | --- |
| profile_id / profile_name | 唯一且与文件名一致；名称满足界面规则 |
| selected_character_id | 为空或指向档案中确实存在的角色 |
| creation_unlocks | 当前版本若有档案级职业创建资格，保存已完成解锁任务与资格；明确配置校验，不以缺字段默认全部开放，角色资源仍独立 |
| settings | 主/音乐/音效/UI音量、镜头、窗口/分辨率、图形预设与垂直同步，范围严格校验 |
| legacy_import_receipts | 新档明确空数组；导入凭证按独立v1严格结构与语义校验，和角色同档提交，删除角色保留deleted记录防重复复活 |
| characters | 最多6个，角色ID与姓名在档案内唯一 |
| character.identity | 姓名、职业、体型、肤色/发型/配色、创建时间 |
| character.life_state / pending_death | active需正生命且pending_death为null；awaiting_respawn需0生命及完整死亡凭证，按死亡保存合同恢复死亡页，不自动活体修复 |
| character.progress | 累计经验、生命/内力/体力、银两、十二转等级/路线、各阶段晋级任务及普通/升天点数、主线/区域进度、门派 |
| character.inventory / equipment_bag / warehouse | 容量等级、堆叠物和装备实例；不允许同一实例出现在两处 |
| character.warehouse_silver | 仓银独立于随身银两，范围0～9007199254740991；新建/已知旧schema1～4导入为0，新格式缺失拒绝；按17仓储合同与物品/费用/修订同事务保存 |
| character.loadouts / active_loadout_id | 明确主/辅助组及当前生效组，按完整槽位定义保存；组ID有效，定义/资格/实例归属严格校验，备用不叠加属性，不冻结旧11槽 |
| character.gems | 独立6位：武器、衣服、内甲、护手2、靴子；类型、品质与实例归属校验，当前有效性由角色资格/对应装备重新计算，不存一份可能失配的加成 |
| character.skills / qigong | 普通/升天武功、普通/升天气功、反气功、已学秘籍、分配点数与前置；气功/升天点升级区间及covered_level按14发点合同，派生有效等级不另存 |
| character.cultivation | 普通历练独立余额、升天历练进度0～9999及待领取天机石精确数量；按14合同4.6持久化，待领不是实际物品，不能与背包天机石同时记作所有权 |
| character.special_resources | [14资源合同](14-职业创建与成长采用合同.md#44-三职业特殊资源与基础状态)的障力当前量/恢复余数、独立愤怒点、和弦/循环/剩余步、充能/护盾互斥状态；按职业显式字段校验，不给不适用职业补空蓝条 |
| character.quests | 主线、区域、晋级、披风、制造、扩容与委托的唯一进度/领奖记录 |
| character.random_state | 固定格式种子和消费位置，战斗/掉落/强化使用同一明确序列 |
| character.timers / effects | 技能/药品冷却及角色效果剩余世界步、来源/叠加标记；装备组剩余交互时长另记，不从保存日期推算 |
| character.activities | 活动轮次/尝试ID、入场提交、阶段、时限剩余、必要逻辑快照、已结算事件；空活动明确为空集合 |
| character.customization | [18配置中心](18-角色参数配置中心.md)的覆盖版本、显式字段与最近配置记录；空覆盖为空映射，不复制全部全局定义 |
| character.location.map_id / position / yaw | 明确场景ID、有限坐标、合法入口/位置、非阻挡位置与安全高度；不能只存一组无场景归属的坐标 |
| character.saved_at | 保存时间只作展示，不决定奖励、刷新或限时付费 |

装备实例包含唯一ID、定义ID、类型化成长数据与来源。普通装备的强化/合成、进化/提真/武勋等分开；宝珠保存自身品质，不把一个随机稀有度倍率用于所有武器防具。各类型所需字段必须明确校验，不增加无用途字段或缺值补普通。披风引用已解锁外观/显隐，预览不写正式装备。实例ID不可复用，同名装备不因排序合并。

所有权、主动装备条件、当前生效条件分开。官网明确宝珠在隔体传功后保留原角色而暂时失效，资格恢复后重新有效；该合法状态不能静默删物或一概拒绝读取。主动穿戴仍检查140级/四式等条件，未知定义、错误槽位、重复实例和未声明状态不能借此放行。主/辅助切换不得复制装备、刷新技能冷却或把两组属性同时生效。

等级、最大生命、最终攻击防御、护体后伤害、气功有效等级、任务门开关及已击败首领由持久进度推导，不能存两份相互矛盾的值。14职业核心/次级属性以[基础成长合同](14-职业创建与成长采用合同.md#21-基础属性与成长采用值)按经验等级和实际晋级重算；迟做一式的基础属性补齐不保存另一份可重复发放的奖励。当前生命/内力/体力独立保存，升级提高上限不自动填满。

累计经验语义范围为0～[14经验合同](14-职业创建与成长采用合同.md#43-等级经验与跨级满级结算)的180级阈值，不以通用JSON整数上限放行超满级坏档；不保存隐式溢出经验银行。经验结算结果分别记录原分配、实际入账与满级溢出，网络重放复用同一结果；不能在客户端按本地另一条曲线重算。

反气功等级预算与十二转开放由经验/晋级推导，见[14点数合同](14-职业创建与成长采用合同.md#41-反气功等级点数与解锁)。持久化技能ID/投入、合法道具来源及剩余时长和明确配置覆盖，不另存可重复领取的等级赠点余额或生效装备预算。换装导致超预算时的分配清空与装备变更同笔保存；合法失效与非法超预算快照分别处理，未知技能、负投入、伪造道具来源不能自动修正。

U33允许角色自定义覆盖：等级仍由经验推导，最大生命/最终攻防等先计算规则值再应用明确覆盖；覆盖不是另一份派生缓存，清除时重新计算。配置中心直接修改实际物品/任务/资源进度，并记录配置来源，不产生第二份角色数据。正常玩法合法状态与用户配置例外显式区分；未知定义、重复实例、非法JSON仍拒绝。

职业起点按[14采用合同](14-职业创建与成长采用合同.md)显式配置：本项目新建角色1级0转是改编，历史80级0转乐师只在参考库保留，不直接导入为新建模板。等级与已完成晋级仍独立校验，不按等级自动补任务。创建初始化、晋级与初始装备授予均有独立去重标记；不因当前直接创建方案而放松未知资格字段检查。

升天武功按[14转换/初始化合同](14-职业创建与成长采用合同.md#42-天机石转换与升天武功初始化)保存每技能实际投入点数/付费版本、未分配升天点、等级/奖励/转换/配置入账与初始化出账汇总。正常来源总额须等于当前未分配+投入+已退款出账（另计明确配置调整）；不能只存技能阶段、读档后按现价猜退款。天机石任务消费与转点分别结算，初始化输出实物时不同时补点。损坏/不守恒记录拒绝；正常初始化后的账与物品/阶段同笔保存，重复保存和LAN重放不产生新退款。

升级发点按[14逐级发点](14-职业创建与成长采用合同.md#45-升级发点共享预算与有效等级)持久保存covered_level与最多179段完整/不重叠区间，含发点规则版本与实际两类收入；正常、升天后和配置跳过分开。当前等级不能高于已处理水位，配置降级可低于水位但不清除已经处理历史；损坏/漏段/未知规则版本拒绝，不重算并重发缺失奖励。区间与经验、晋级资格快照和点数同笔提交，普通/升天气功共用自有预算，装备有效等级不写入自有点数账。

历练/天机石生成与气功洗点按[14事务](14-职业创建与成长采用合同.md#46-历练天机石生成与气功洗点)保存：历练分配/入账/溢出、升天进度与待领取、实物领取，以及山参消费/自有分配退款同笔处理。死亡保留修行积累；满级不截断普通历练/合格升天进度来源。待领只由明确生成流程产生，升天武功退款不能借它绕开满包拒绝；洗点不重置covered_level或冷却，涉及其他角色持续效果的重算也纳入房主结算接收者。

气功/反气功分配引用[来源身份映射](contracts/武功气功来源映射.v1.json)选定的稳定项目ID，不能只存显示名或网页行号；来源改名不新建角色技能ID。反气功命中标记/随机位置随动作快照保存，攻击者每项0～180步冷却、目标具体气功ID/施加来源/减级/1～180步效果按[14规则](14-职业创建与成长采用合同.md#47-武功来源身份与反气功命中规则)校验并去重；强弱来源分别计时，不存一份到期后直接加回的旧有效等级。反气功对怪防御由预算重算，不能另存可重复叠加的奖励。

神女状态按[20合同](20-状态技能与效果采用合同.md)另保存系列周期相位、区间累计路程、阎王爆实际生命损失、复仇条件/转移链接、传染根事件和错乱已选动作。参数用稳定技能/效果ID和有限快照，不从中文名称推类型。安全解除/死亡/免疫不兑现自然到期爆炸，旧冷却不因学习更高阶段重置；所有多接收者变化进入房主同一结算链。

怒气计量/自然及强制来源、出血系列相位/伤害快照/实际施加与奖励归属、血雨恶魔挑战绑定/剩余窗口/成功冷却按20合同保存。是否愤怒由现有来源推导，不另存布尔缓存，也不因血雨恶魔核心仍在而补回已被解除的怒气。血雨恶魔只在显式支持完整战斗快照的NPC武者活动触发；退出仍存同一活动/对手及全部战斗实体，缺对手/快照拒绝，不用野外刷新替代。治疗不能赦免到期失败，冷却不因死亡/重分配/配置跳级重开；配置解除明确标记而不记正常获救。

气功学习按[21合同](21-气功学习与秘籍采用合同.md)区分普通条件开放与140项秘籍资格：前者由进度推导不存重复开关，后者在现有学习记录存明确秘籍定义ID/来源，不同时再存目标气功已学布尔。书消费与资格同笔提交，洗点保留；卢90任务资格从唯一任务交付状态推导。正常快照缺书/任务却有分配须拒绝，显式配置可确认保留已知技能但不生效，不从分配等级反向补书或任务。训练活动保存同一尝试与剩余时限/敌人状态，不能重进白开新局。

新建角色按[22模板](22-角色初始模板与低阶教学采用合同.md)完整验证后一次生成2个装备实例、两堆各5药、2000两及本职初学阶段；医师另有疗伤。只在创建命令提交入账，NPC/旧档导入/读档/复活/角色切换不重复执行模板，不能凭缺武器补赠。空布局是显式所选28槽/6宝珠空配置，不以缺字段当空槽；新角色当前资源置派生初始上限，此后保存只存当前量。裸攻击与武器两端分别参与统一攻击区间，角色档不存两套最终攻击缓存。

### 4.1 计时与活动快照

世界时间使用60Hz整数步，持续2小时为432000步、20分钟为72000步、眩晕10秒为600步。剩余步数须为非负整数且不超过对应规则上限；角色效果包含定义ID、来源事件、层数及必要触发状态，不保存可失配的最终属性加成。装备组冷却保存剩余整数毫秒0～1000；离线冻结，不保存系统单调时钟绝对值。

普通敌人现场重建不清除角色冷却、负面状态或成功BUFF；死亡、解除或技能明确改变效果时按对应规则执行。角色未完成动作跨保存需要保存动作ID、剩余阶段、已扣资源及已命中集合，或只在动作结束后捕获保存；不得保存已扣费却遗漏待结算动作。正式实现选择“动作及其全部派生事件结束后捕获”，活动战斗快照除外。连击追加/箭矢延迟队列与回避一次增幅按[连击合同](contracts/连击与回避追击.v1.json)记录，不能只等动画结束漏存已付资源的延迟伤害。

进行中讨伐必须在固定步边界保存逻辑快照：玩家和9名伙伴及敌人的稳定实体ID、位置/朝向、生命/资源、动作阶段/剩余步、冷却/效果、仇恨/目标；召唤物、未结算投射物及命中集合；安全罩/红区/人数圈/四珠状态、阶段进度、弱点计数、时限和随机消费位置。特殊资源快照包含动作级愤怒点消费/充能已发/和弦随机已判标记，不能仅靠目标命中集合推断资源是否已结算。只记录存在的逻辑状态，不保存NodePath或引擎句柄。

活动保存不退回阶段开场，不重置敌我生命、已消费道具、机制进度或随机序列。恢复先验证全部定义/实体引用和阶段一致性，再重建表现；失败明确报错，不清空活动继续玩。胜利或失败提交时移除活动现场快照，保留尝试与奖励结算记录；退出后不额外重新生成同次掉落。

角色手动保存、暂停退出和自动保存均捕获同一一致状态；活动战斗中允许快照，普通未完成动作则等到动作结束再捕获。若无法取得一致状态，显示尚未保存，不提前写“保存成功”。这些是待实现合同，必须实测持续伤害、飞行投射物、濒死及机制倒计时的保存往返。

## 5. 旧档兼容与导入

已知历史格式为schema1/liuli-0.3、schema2/liuli-0.4、schema3/liuli-0.5、schema4/liuli-0.6。旧单槽路径为根目录 `save.json`；只通过明确的导入操作读取，不自动覆盖或移动源文件。

迁移先按原版本严格校验，再转换为统一已知旧结构，最后映射schema5；四种版本差异/物品ID/身份与去重见[旧档导入JSON](contracts/旧档导入.v1.json)，解码源码证据完整保存于[旧结构基线](reference/旧存档结构基线.json)。schema1补原固定装备/默认字段，schema2迁两强化并补三扩展，schema3只迁装备且保留已有武学/区域/门派，schema4直接读取；不能按一个通用缺字段补齐器接收未知旧档。

新角色ID按目标档案ID与来源原字节SHA256确定，装备实例再按旧容器路径/序号确定；两件同定义同等级仍是不同实例。目标档案记录来源摘要/版本/新角色ID，源文件只读不移动。同字节来源再次导入同档案返回原结果，不再次建角色/发物；不同字节只展示新的独立导入预览，不自动认作同人覆盖或合并。凭证和新角色在同一档案事务提交，写失败重试不复制物品。

旧解码器本就用当前liuli0.6规则校验四版本，本项目明确仅支持该已归档基线：旧起点[0,100,260,500,850,1300,1900,2700,3700,5000]，最高10级/5000经验。L<10时，目标累计经验=新L级起点+整除((旧经验−旧L级起点)×新L升级花费,旧L升级花费)；旧5000对应新10级起点。这样保持旧等级和本级完成比例（按新整数经验向下取整），原total_exp保留来源证据，不宣称目标数字不变。预览必须显示原值/级别/比例/目标值和修改理由，不能静默按新表降级。自改旧曲线没有已核导入档则拒绝，不从生命或技能等级猜曲线。

旧角色covered_level设转换后L；2～L登记legacy_import_skip且正常发点0，L=1无区间。原版没有的新气功/升天/反气功点均不补发，旧四剑技等级另保留，之后练回已处理等级不二次领奖。源档、原值和这笔导入来源保留。七旧装备定义/0～3成长/槽位已由[旧装备兼容JSON](contracts/旧装备兼容.v1.json)明确；HP/体力按下述明确转换，[四剑技映射](contracts/旧剑技兼容.v1.json)也已定，schema5导入凭证严格字段仍须闭合后才能实际导入；不得默认截断/补满/重置。实际银两、背包、装备强化、任务/区域、贡献与合法位置保持其对应原值。

新字段明确初始化：旧角色未转职、未选正邪、内力按目标版当前等级满值、额外装备槽为空、仓库为空、旧装备容量不缩减；原装备保持原定义/强化，不新增虚构随机品质。既有四剑技按原数组顺序映稳定ID并保留0～3等级，不扣新学费，不执行22新建教学授予；原未认主但剑气1级记录仍保留为未可用，不能反推任务已完成。旧技能快照原无冷却/BUFF/动作字段，显式初始化为0/无效果；不从当前会话复制。四技能快捷栏与独立旧修行预算由兼容合同维护，不占普通/升天气功点，气功分配为零。若旧角色等级已满足转职，只开放任务，不自动标为完成。

生命先按旧规则校验正整数1～120+30×(旧等级−1)，0生命不属于可导入旧快照，不在迁移时救活。目标上限按已验证的导入剑客等级/0转/实际旧装备/门派/技能计算，不跑新建模板。当前生命取`向上取整(旧当前生命×目标生命上限/旧生命上限)`，保留生命比例，误差小于1点；旧满血恰映新满血，受伤不默认补满。旧HP字段/旧上限及目标值写预览和导入来源，不能谎称新旧数值完全不变。

旧体力是有限0～100小数；先严格校验原JSON数字，再以原数字的十进制/有理数表示向下取整为目标整数体力，损失严格小于1点，预览明确显示。此为一次性有意量化，不是用int()截断非法小数配置；负数/超100/非有限仍拒绝。原数字词元留来源，目标剩余恢复等待设60世界步/恢复余数0，之后按23合同逐步回复，不借导入补满或结算离线时长。新内力按下述明确初始化；旧快照没有怒气/护盾现场来源，不能从当前会话带入。

旧7件装备采用定义见[兼容合同](contracts/旧装备兼容.v1.json)，浮仙剑只引用剧情物品权威定义，不建第二份。旧weapon→primary.weapon、armor→primary.body、包顺序保留，其他组槽为空；同定义/等级不合并实例。定义继续可解析：`fuxian_sword / ironwood_blade / refined_blade / frost_edge / menial_robe / leather_armor / dark_iron_armor`，保持原属性，不能借迁移替换成不同条件的新装备。未知版本、缺失定义、非法槽位、重复实例、超上限强化、矛盾任务/贡献拒绝导入，不丢弃错误记录继续运行。

### 5.1 导入凭证与删除记录

[凭证JSON Schema](contracts/旧档导入凭证.schema.json)定义v1必填/类型/枚举/ID格式和拒绝未知字段；[导入合同](contracts/旧档导入.v1.json)的receipt_policy维护语义校验，结构通过不代表来源关系正确。每笔以目标档案ID+原字节摘要+导入档ID唯一，保存来源schema/content、目标角色ID、转换数值、四剑技原等级、原装备路径/定义/等级到目标实例ID、导入时档案修订。无本机绝对路径或外部数据库索引。

四版本必须精确配对，不能只测两个枚举各自合法。体力源词元必须完整匹配JSON数字并按有理数解析，禁止eval/容错解析；源级别/上限、目标经验/HP比例、技能等级及实例路径/摘要交叉核对。凭证历史按固定导入档v1验证，目标初始上限133+7×(旧等级−1)，不能因角色后来配置/升级而用当前上限否定旧凭证或重做换算。

present要求当前恰有该角色；明确删除角色时同事务把凭证改deleted，角色ID不再存在。保留摘要/映射用于防重，同源再次导入只提示先前已导入后删除，不复活、不补包；重新建立副本必须是另行明确设计的克隆操作，当前导入不隐式承担。除该删除标记外凭证不可被普通玩法重写。

实例映射指首次导入归属，不要求该实例永远留在初始槽，之后合法移动/出售/消耗不会令凭证失效，更不能补回已消费物品。原路径必须唯一，按已规范化旧结构标识，不能拿当前容器序号重建ID。导入修订不得晚于当前档案修订；坏摘要/字段/重复来源/矛盾删除引用拒绝，不通过扫描角色猜一个修复凭证。

这只闭合导入凭证，完整schema5各系统字段、旧故事/门派到正式定义映射仍需总检；目前没有导入程序或用户存档实测。

[死亡与复活保存合同](contracts/死亡与复活保存.v1.json)明确新档两个生命状态。死亡/活动失败/已消费物品及唯一凭证同笔提交，保存退出或读档不再结失败/补血；旧1～4源0HP仍拒绝。普通复活先验工棚锚，修炼房按已保存条件和显式选择检验原死亡位置或泫勃返回锚，再原子切active并恢复实际资源/清待死，保技能药物冷却，不发初始包；坏锚/位置保待复活不选替代位置。死亡取消动作后应能捕获终局，不能被“等动画和后代完成”卡死保存；已合法独立状态与取消未发攻击的区别按源规则保留。

## 6. 保存流程与故障要求

1. 固定步事务完成后捕获一致快照；死亡按明确awaiting_respawn/0生命及结算记录保存，不能延迟到回城或写成active。
2. 复制档案，替换当前角色，完整验证所有角色、实例、设置与引用。
3. 目标文件同目录写唯一临时文件，拒绝占用已有临时文件；写入后flush并关闭。
4. 通过DirAccess在同文件系统提交替换，只有成功才更新“已保存”。不先删除旧档。
5. 失败保留旧文件和当前内存进度，显示路径/原因，清理本次创建的临时文件；旧临时文件不自动覆盖或当作有效存档。

FileAccess/DirAccess替换已有文件、权限拒绝、异常中断、磁盘写入失败和旧文件保留都必须在Godot4.7.2/Windows下实测。不能沿用Rust版ReplaceFileW的通过结论，也不能在失败时改成删除旧档再写。

成功事务触发自动保存；失败保存不撤销已经完成的内存玩法事务，但必须保持“未保存”状态。重新退出前需要确认；不得显示保存成功后静默丢失进度。

## 7. 事务与测试隔离

### 7.1 局域网与多开补充

同一档案文件仅一个实例持有写锁；不禁止不同档案/独立根的多开。锁获取失败不偷偷改路径或复制存档，异常锁按实际进程与系统文件锁判断。[19联机合同](19-局域网组队聊天与多开.md)要求客户端只保存自身角色、房主保存世界和持久结算日志：新增`worlds/<world_id>.json`，同目录原子替换，包含协议/规则版本、参与角色修订、活动/队伍状态及待确认/已确认结算ID。

网络命令去重使用`world_id + character_id + settlement_id`，不使用会重分配的Peer ID作为持久身份。房主日志持久成功后才发结果，客户端应用/存档成功后确认；重连只重放未确认结果，客户端持久去重。跨文件/跨机器未确认状态须明确展示，不宣称全体同时原子保存。房主失败不发已提交结果，客户端失败不重抽或重复扣票。

每笔记录包含世界序号、请求ID、规则版本、前置世界修订号、随机前/后状态和全部参与者结果。各参与者保存角色ID、结算序号、前/后修订号、变更及校验后的结果快照、确认状态。多人经验、门票或掉落一次业务提交写入同一房主文件，不能先通知一人成功、再因另一人写入失败回滚半笔。

房主流程为校验→在副本计算世界/角色/随机结果→持久写入新世界快照与待确认日志→发布内存结果和网络消息。日志写失败整笔不提交，保持原随机状态；成功后崩溃则按日志恢复，不再次计算随机。房主自己的角色也作为接收者写入档案并确认，不能假定房主两个文件天然原子。

客户端收到结算时要求前修订号等于当前已提交修订，按序应用结果和`network_receipts`到同一档案快照后确认；保存失败保留待保存内存，暂禁该角色新的经济/任务/配置事务，不阻止其他玩家。重发同笔只重试保存/确认；序号缺口请求缺失结果，不跳过。不能把重复结果当重新获得的经验/物品。

`character.network_receipts`按world_id保存最后连续应用序号及角色结果修订；房主按角色保存连续确认水位。仅当该业务全部接收者确认、世界新快照已成功持久后才能压缩对应完整事件；角色修订、确认水位和必要最终快照保留。旧序号重试只回复已提交状态或同步快照，不重新发奖。未确认事件不按天数或条数自动丢弃；空间不足明确停止新业务并提示，不删除记录继续游戏。

重连先比对世界ID、角色ID、协议/规则哈希、接收水位及前置修订。客户端离线另改角色或导入造成分支时拒绝直接合并，并显示两边修订；用户可退出房间继续本地分支，或先导出本地角色再明确恢复房主保存的分支。禁止按时间戳自动选择、覆盖或把差额再次结算。手动回滚/篡改本地文件不在防作弊承诺内，正常保存链的重试去重必须保证。

聊天记录不持久化，房间口令不写角色/配置方案；房主结束世界保留必要结算记录。日志清理按连续确认水位执行，断线角色的10秒实体/120秒席位规则见19合同；普通角色单机文件规则继续有效，数据库始终不使用。以上字段均为计划结构，Windows替换故障与多进程实际实现仍未验证。

容器槽数、重量整数克、扩容等级/费用及复购会话规则见[17物品合同](17-物品背包与经济采用合同.md)。重量和容量由物品与扩容进度推导，复购记录不写持久角色快照；不得把已售出实例同时计入背包。全部逐物品定义尚未闭合，本方案未实现。

创建/删除角色、换装、扩容、仓储、批量交易、拾取、强化、合成、转移、制造、学习/洗点、任务与门派都检查完整前置后一次提交。随机结果和相应资源变更属于同一个结果，重复请求不重新抽取。

测试只写 `target/verification/` 下独立根目录，生成档案和旧档样本，验证后清理。用户实际存档不进入测试；本任务不读取或修改用户LOCALAPPDATA中的游戏进度。

修炼BUFF保存采用修炼之门合同`timed_buffs.persistence`：世界必存`world.training_gate_clock_steps`，显式新世界为0；角色必存`training_gate_buffs.by_world`，新建与已知旧档转换显式为空。每世界存`observed_world_step`与四主题的`last_claimed_cycle_or_null`、`remaining_world_steps`，不冗余保存绝对到期值。重连用权威世界步差扣时，时钟倒退或新格式缺字段拒绝；整世界离线冻结。死亡保留领取账本与时长，失活期间仍按世界步扣时。

修炼每日任务保存`character.training_gate_daily.by_world`，新角色与已知旧1～4转换显式空账本；每世界存观察步与八任务状态、接取日或null、最近交付日或null，绑定物品保存角色/世界/任务/日来源。任务无独立收集数量缓存。载入验证状态/实物/收据一致、世界时钟不倒退，先处理5184000步日界过期再接收动作；新格式缺字段拒绝。

修炼怪物状态由修炼怪物与刷点JSON维护，世界保存432稳定槽及普通generation/复活等待或召唤周期状态、生命/位置/朝向/观察步，并保存战斗动作/冷却/状态及唯一死亡收据。重载不回血，召唤过期移除不产生击杀；新格式缺槽拒绝，已知旧档仅显式新世界创建初始化。

便携回城按便携传送与修炼限制合同保存已接受动作ID、真实堆引用预留、源地图/位置、剩余0～180步和同组剩余冷却；只有一次实物所有权。恢复严格验证物品/动作/世界与源目标规则，禁止重载立即完成或刷新读条；成功扣1/移动/冷却/收据同事务。
