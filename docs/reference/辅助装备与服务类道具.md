## 2. 辅助栏已经明确与仍待核实的部分

官方旧道具明确列出“使用/激活辅助装备栏”，V25原图确认该页仍存在。它与宝珠页是不同系统，不能把宝珠6格用于推断辅助装备6格。

社区资料解释为备用的第二套防具、武器、首饰、内甲、披风/门派服，通过Page Down切换，外观随生效套装变化，主副两套属性不叠加；并说灵兽不放辅助栏。该解释可作交叉参考，仍需当前官方说明/图示核对详细限制。

社区对“弓箭位置不变”的文字有武器/箭矢语义歧义，不据此直接决定两个套装共用弓武器或弹药。精确槽位、切换条件、冷却秒数与宝珠联动继续核对。

## 3. 当前单机设计采用

以下是项目方案，不伪装成官网原值：

- 不实现现实付费或账号订阅来解锁辅助栏；保留辅助装备功能，基础界面可查看，装备和切换仍检查实际角色/物品条件。
- 采用互斥生效套装，只有当前生效套装进入属性计算，不把备用装备当免费叠加属性。
- 预览、编辑和启用不同；切换走统一规则命令，验证全部槽位/职业/等级/路线和实例归属后一次提交，失败全部不变。
- 切换不能复制物品、刷新技能冷却、取消已经生效的负面状态或重复结算强化/宝珠加成。外观、HUD与存档必须反映同一生效组。
- 更换装备冷却是V25已列机制；秒数、暂停时钟及动作中限制待本地采用表明确，不能先在代码补默认秒数。
- 套餐的其他加成不因为“辅助页基础可用”就全部永久赠送；相关系统逐项设计，正式道具必须有明确作用范围、持续、叠加和取得方式。

## 5. 数据与验收要求

需要明确生效组ID、两套装备的实例归属、预览组、每组允许槽位、资格检查、宝珠关联、切换时序/冷却与保存恢复。不能一件实例同时在背包和两套槽位中，也不能只改人物外形而属性仍来自旧套。

档案级服务范围与角色资源独立性分别保存；若本地采用道具持续效果，必须明确世界时间/离线/暂停策略，不能隐式读取服务器时间或要求账号在线。

土灵符存点、吸魂、凝神珠、采集、武勋和负重列入参考覆盖，不能因为它们出现在旧商业礼包中就认为无需系统实现或直接照发所有加成。当前版本与本地采用尚未确定的字段继续登记，不以“辅助页有标签”作为功能完成。
