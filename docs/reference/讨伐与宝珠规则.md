# 讨伐战与宝珠规则

核对日期：2026-11-13。依据[官网讨伐战资料](http://rxjh.17game.com/data/tsplay/202106/65546.htm)及其原图，结合已查看的[V25装备分页](V25图示核对记录.md)。下列为该公开页明确规则，不表示已经运行最新客户端实测，也不把未读/未公开参数补成默认值。

## 1. 讨伐入口与条件

| 项目 | 官网公开值 |
| --- | --- |
| 角色条件 | 140级及以上，且完成升天四式 |
| 入口 | 银币广场，讨伐管理员 |
| 队伍 | 10～30人，1队长；全队等级、转职、次数及入场券均需符合 |
| 入场券 | 每名参战角色持有；在讨伐管理员处购买，1亿两 |
| 时间/次数 | 原页写每日1:00～23:00，每周5次、周一0:00刷新 |
| 难度 | 本页FAQ写当时只开放简单；不能据此声称其他当前资料一定没有更多难度 |
| 胜利 | 规定时间内击败堕落的地狱火龙 |
| 失败参与奖 | 根据副本次数，每次5枚冰魄水玉 |
| 成功BUFF | 地狱火龙的认可：对怪攻击+100、对怪防御+100，2小时 |

组队、现实开放时间、NPC伙伴门票和本地保存/重开方式需在单机设计中独立列采用值与理由。不能假装连接其他玩家，也不能为了单人可过而直接删掉合作机制。

## 2. 战斗机制与奖励

官网描述包括召唤部下、周围随机绿色安全罩、红色爆炸区、数字人数圈、带数字的四个如意珠和弱点阶段。

- 人数圈要求对应数量角色站入；人数不正确会触发全体伤害。
- 四个如意珠需要达到各自标记的攻击次数，不能只打掉任意一个就算全部完成。
- 多次解除机制会推进弱点，弱点珠变红后首领眩晕10秒且不攻击。
- 原页有队员贡献排名和追加奖励；伤害/机制贡献不能由UI随机显示。
- 击败后奖励在首领四周生成，原网游规则无拾取优先权。单机队伍如何分配需明确，不能复制同一掉落给每名伙伴再全部交玩家。
- 讨伐证明、宝珠、装备/秘籍、经验/历练和参与奖是不同结算，不因同一首领多次死亡消息重复生成。

## 3. 宝珠种类、品质与槽位

| 分类维度 | 官网公开内容 |
| --- | --- |
| 类型 | 武器、衣服、内甲、护手、靴子，共5类 |
| 品质 | 普通、高级、稀有、传说，共4档 |
| 槽位 | 共6个：武器1、衣服1、内甲1、护手2、靴子1 |
| 装备前置 | 140级及以上且升天四式 |
| 普通来源 | 讨伐副本概率掉落 |
| 高级来源 | 宝珠进化 |
| 稀有来源 | 宝珠进化或制作 |
| 传说来源 | 宝珠进化 |

5类×4档表示公开类型/品质组合，不是已经取得20个完整官方物品ID。两个护手宝珠位属于同一类型的两个槽，不生造第六类“第二护手宝珠”。也不能仅由宝珠6格推断主装备全部槽位。

宝珠不可丢弃、NPC出售或与其他玩家交易，可以存入个人仓库。各宝珠可提供对怪攻击、对怪防御、生命等不同属性。只装一颗也有效，不要求集齐6颗。

效果随角色转职和对应装备的强化等级变化；原页明确使用道具和BUFF无效，不能把临时强化/属性效果重复算入宝珠基准。完整每类/每档公式继续核对，不统一猜为普通首饰加成。

## 4. 资格变化与物品保留

原页对隔体传功明确：宝珠道具不转移，属性暂时失效，原角色等级与转职重新符合后恢复。

因此所有权、允许装备、当前是否生效必须分开判断。合法事件导致资格暂时不足时，不能静默删除宝珠、转给接收角色、强制降级宝珠或把存档一概判坏；也不能允许不符合条件时继续享受属性。未知定义、重复实例等数据错误仍应明确拒绝。

## 5. 宝珠进化

地点为泫勃派东面的宝珠管理员，菜单“宝珠进化”。费用1,000万两。

官网文字说明：成功消耗低级宝珠并得到更高级宝珠；失败消耗1个低级宝珠。实际查看进化原图，示例界面有两个宝珠输入和“宝珠幸运符”位置，箭头展示结果。

两个输入是否严格要求同类/同品质、幸运符是否可选、加成比例、消耗优先级与各档成功率，不能仅凭该示例图推断为已知规则。费用、成功/失败结果及实例变更在一次事务内提交，取消不先扣1,000万两。

## 6. 稀有宝珠制造与分解

原文明确在“特殊制作”中，用200个讨伐的证明（地狱火龙）制造稀有宝珠。原图可见稀有宝珠目录和火龙武器宝珠[稀有]制作成功反馈。

图示中可读到火龙护手、内甲、衣服、武器宝珠[稀有]，列表带滚动；未显示的靴子具体品名不据此臆造，类型本身已有文字表支持。

原文称分解稀有宝珠可得“50个左右”证明，属于近似描述，不把它写成固定50、上下限或概率分布。额外制造费用、产出数量、熟练条件和精确分解表继续核对；进化1,000万两不能自动套给制造。

制造原图还可见“武器制造、防具制造、爆毒制造、道具分解、特殊制作”和熟练字段。必须作为制造知识范围记录，不用一个“强化”按钮替代整个制造系统。

## 8. 设计与验收落点

宝珠不是灵兽召唤用的“灵兽宝珠”，不能因为名称都含宝珠就共用道具类型。主装备、辅助装备和宝珠分页的各自规则独立核对。

需要覆盖六槽实例唯一、双护手不合并、单颗生效、等级/四式边界、实际强化与BUFF区分、合法资格变化失效/恢复、进化取消/成功/失败、制造容量/材料、分解确认和副本奖励去重。具体本地规则与公式确定后记录项目采用值，程序不读空字段兜底。
