## 3. 强化披风分解确认

来源：[gs7.png](http://rxjh.17game.com/event/2026/content/images/gs/gs7.png)。

原图明确为披风分解界面及第二层通知：说明目标是强化过的披风，要求输入当日日期4位数；字段标注为`MMDD`，并提供确认/取消。

此图不能证明所有披风都有相同强化上限、产物或销毁规则；具体物品类型、分解需求与奖励继续逐类核对。

## 4. 对设计与验收的影响

装备分页、装饰位、物品类型和属性生效范围需要完整建模，不能只做空标签，也不能把辅助装备/宝珠无依据地当作普通首饰或宠物。各页属性是否同时生效、是否为切换套装，必须有独立证据。

现代界面可重做布局与防误触样式，但若修改官网确认方式、分页或冷却交互，要写清原机制、项目方案和理由，验证不可重复提交、取消不变、目标切换后重新核对。
