# 开发规范

更新日期：2026-11-13。适用于Godot4.7.2/GDScript工程及文档、资源、测试与交付。会话中用户给出的项目约定继续有效，完整要求见[用户需求与执行约束](00-用户需求与执行约束.md)，阶段严格按[开发计划](06-开发计划.md)执行。

## 1. 修改原则

精准修改，只处理当前阶段需要的文件。找到问题来源后直接修正，不增加静默兜底、重复规则、空模块、失效资源或临时补丁叠层。替换完成后清理无用途实现；未完成验证前保留必要的参考源码。

不改动无关格式、编码和换行。没有内容变化的文件不应出现在Git更改列表。工作区没有Git元数据时使用前后SHA256核对，不为此初始化仓库或伪造提交。

不建立、连接或修改数据库；若未来明确涉及数据库，仅提供对应SQL供用户操作。测试使用隔离存档，不碰用户真实进度。验证结束关闭本次启动的游戏、引擎及辅助进程，不关闭用户原有进程。

## 2. GDScript与状态

- 使用Godot4.7.2标准版和类型化GDScript，变量/参数/返回值标注具体类型；动态JSON在边界完整检查后再进入规则。
- 用枚举或单一状态表达互斥动作、任务、面板及应用阶段，不用多个布尔值组合矛盾状态。
- 业务错误返回明确错误码/信息和字段上下文；错误不可被空字典、默认装备、强制截断或跳过元素掩盖。
- 数值来自唯一正式配置；界面文案不能反向作为数值来源，表现层不能直接改进度。
- 规则对象不依赖渲染/文件系统，固定步和随机种子可控，便于独立测试。
- 命中、死亡、奖励、随机与事务按明确顺序去重；信号连接和释放不能重入结算。
- 只在真实复用或明确边界时抽取接口，不为未来候选系统建通用框架。注释写约束和原因。

## 3. 场景、资源与输入

所有世界节点归属当前会话，退出统一释放；投射物、音效、特效、飘字和消息有界。暂停、切换角色、返回选角清理缓存动作与预览；不能让上一角色资源影响下一角色。

UI先处理焦点、模态和中文输入，再向规则发命令；非交互HUD允许地面点击。动画只显示规则结果，不能决定伤害、无敌或奖励。

资源清单严格检查路径、类型、骨骼、命名动画和许可；缺失或损坏显示具体原因。开发几何体是显式测试场景，不作为运行时加载失败的替代物。

## 4. 版本、依赖和配置

固定引擎与导出模板4.7.2，使用标准版；不顺便升级或增加C#/.NET/Rust扩展。新增插件需要明确现有Godot组件无法满足的用途，并维护版本、许可证和校验来源。

`.godot/`、`target/`、本机绝对路径配置、临时脚本、测试存档和下载半成品不进入正式源文件。必要`.uid`、导入参数与导出预设随工程维护。正式发布只使用一套JSON配置和一套Godot规则。

## 6. 每阶段结束

1. 核对实际差异、来源规则和数值一致性，删除仅本次产生且无用途的临时文件。
2. 执行当前阶段必需检查；失败先修来源，再复测失败项与受影响范围。
3. 更新09记录和06状态，证据与未执行项齐全，不能把文档设计当程序完成。
4. 核对存档隔离、资源许可、进程退出和无内容变化文件。
5. 本阶段通过后再进入下一阶段；只有既定程序、测试、美术与发行都完成才宣布系统完成。
