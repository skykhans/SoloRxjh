# 英雄主武器基础定义

更新日期：2026-11-14。状态：基础装备元数据已设计，成长及取得未闭合，未实现。结构化权威为[英雄主武器基础定义](contracts/英雄主武器基础定义.v1.json)。

## 1. 身份与来源

六英雄普通主线各13阶段（封印、五次普通转职、七式升天）共78件；目录另列29件真武器，共107件。六封印复用[初始模板](contracts/角色初始模板.v1.json)的原ID与唯一定义，本合同新增101件，不重复创建封印。每件回指[来源阶段映射](reference/英雄主武器阶段映射.json)，保留目录名称、攻击范围、装备等级；未见的真火龙刀三式不补造。

白龙刀、黑灵剑及青雨丸属其他分支，本目录不把它们当主武器某阶段。源名称重复也不合并，例如同名不同等级伏魔花灵剑分别有独立ID。

## 2. 基础字段与项目取舍

每个新定义明确职业、武器族、武器槽、正邪路线（一阶另允许中立）、等级、角色rank、独立武器stage、普通/真、非武勋标识、攻击上下限、堆1、重量、角色绑定、权限和来源。全部阶段重量沿该职业封印：刀1800克、剑1000克、弓900克、枪1800克、杖1000克、血雨丸200克；这是项目恒重选择，非官网重量。

火龙刀/血雨丸六转保留目录110级并另检查rank6，正常角色六转任务最低115，所以不能110级绕过角色任务。其他四英雄该阶段目录为115，分别保留。

允许本人仓储与两组武器槽穿戴，禁止直接使用、卖店、丢弃、玩家交易、复购和普通分解。血雨丸相应公开禁项保留；其余英雄保护权限和仓储是项目设计。具名晋阶/提真/转移配方可以消耗指定主武器，不由“禁止分解”推成永不能推进。

角色只有一条初始主武器血统。只允许具名配方生成下一件，不直接卖店、不放普通掉落、不因完成角色转职自动赠送。源消耗、输出新ID、血统和收据必须同笔提交。

## 3. 成长依赖

101新定义采用项目真实强化设计上限15，尚不等于可直接点击强化；generic_growth_modes为空，不生成默认铁匠服务。六封印初始仍+0；[31具名强化合同](31-英雄主武器强化采用合同.md)已将107件逐一定名绑定，六封印强化上限现为15，+1主动购买一个石并付费600两，不自动赠物。[32晋阶/提真](32-英雄主武器晋阶与提真采用合同.md)已补95晋阶/29提真和材料来源；强化本身仍不改变stage。

攻击字段只含目录基础值，进入现有攻击快照一次。强化、合成、觉醒、属性石、奇玉、四神和附加显示提升由各自明确来源贡献，不能把复合截图总值当基础攻击再次相加。反气功装备预算也不能从15上限猜逐级表。

[29强化转移](29-英雄武器强化转移采用合同.md)的47配方已有94个正式源/目标定义指针；目标基础定义存在后，仍须成长schema能验证全部继承状态才允许服务。定义存在不代表流程可达或游戏已实现。

## 4. 验收范围

静态核对107个唯一ID、101基础定义逐项来源值、6封印回指、普通主线每职业stage0～12连续、普通/真分支唯一和47配方正式引用。计划运行验收还需等级/rank/职业/路线边界、两组/仓库唯一归属与恒重、坏实例拒绝、所有成长来源贡献、晋阶取得与保存/LAN。D1整体仍未通过。

实例成长统一登记在JSON的instance_growth_schema：11个现有平铺字段，逐项有类型/范围或唯一owner，并验证阶段、真/武勋标识及嵌套来源链。此登记不新增实例容器、不复制数值表；八类加工与附加提升使用同一登记。整数不接布尔/小数/数字字符串，缺字段不补空；六封印和101正式定义均适用。

完整实例按[英雄主武器实例owner](contracts/英雄主武器实例.v1.json)及[根schema](contracts/英雄主武器实例.schema.json)校验，嵌套结构共用[武器结构schema](contracts/武器成长结构.schema.json)。八个身份/来源字段与既有成长字段平铺；普通完整18键，英雄19键。普通不收英雄专属阶段字段。静态真标识、英雄精确阶段和低阶成长边界直接校验；完整来源、加工资格和严格整数token另验。各加工合同“失败原字段保持”指成长结果及其成功凭证保持；真实付费/RNG尝试仍按完整根owner更新最近状态入口和实例修订一次。未实现运行或完成D1。
