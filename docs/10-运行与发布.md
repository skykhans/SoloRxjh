# 运行与发布

更新日期：2026-11-13。Godot4.7.2/GDScript是目标版；当前工作区仍有Rust源码和旧Windows预览包。下列Godot命令属于工程实现后的合同，不能把不存在的入口或旧包当成新版本交付。

## 1. Godot开发与校验入口

使用Godot4.7.2标准版，编辑器和导出模板精确匹配。工程建立后在根目录执行：

```powershell
godot --version
godot --headless --editor --path . --import
godot --headless --path . --script tests/run_tests.gd
godot --path . -- --save-dir target/verification/manual-saves
```

`godot`指向实际安装的4.7.2控制台程序；不存在时先配置具体路径，不自动切换其他版本。`tests/run_tests.gd`和项目用户参数均待P阶段实现。无窗口导入、规则测试和带渲染运行分别记录。

应用默认读取`res://assets/config/`和正式导入资源。用户参数位于Godot的`--`之后；`--save-dir PATH`隔离整个档案目录。缺失配置、资源、引擎版本或存档错误要明确显示原因并非零退出。

## 2. 最终用户启动与操作

目标发行目录包含`SoloRxjh.exe`、Godot资源包、许可、资源清单与本说明；采用嵌入PCK还是外置PCK由导出预设明确，不允许缺包仍显示成功。玩家不需要Godot编辑器、Rust、Blender、网络、数据库或后端。

启动进入本地档案，再创建/选择角色进入江湖。角色创建、升级、职业/装备、铁匠、交易、门派和消息均由本地规则完成。完整按键和面板用途统一见[玩法与功能](02-玩法与功能.md)，本页不维护第二份可能冲突的操作表。

默认档案在`%LOCALAPPDATA%/SoloRxjh/profiles/`；旧单槽`save.json`仅通过明确导入入口读取。备份需在游戏退出后复制整个档案目录；不能只复制某件装备或部分角色字段。

## 3. 导出与包结构

目标预设为`Windows Desktop`，使用4.7.2标准版Windows x64导出模板。预设建立并通过系统测试后执行：

```powershell
godot --headless --path . --export-release "Windows Desktop" target/dist/SoloRxjh-godot-1-windows-x64/SoloRxjh.exe
```

发布工具负责创建全新输出目录、拒绝覆盖既有版本、生成SHA256资源清单并打包ZIP。导出包含实际引用的场景、脚本、JSON、模型、材质、字体、音频及许可；排除测试入口、开发几何、探针、`.blend`、用户存档、缓存、旧Rust输出和本机工具。

Godot引擎许可和随附第三方声明需随发行包保留，字体携带OFL，原创资产来源明确。不能把旧Cargo依赖许可证列表直接当作Godot运行依赖清单。

## 4. 包验收与清理

逐项核对目录/ZIP文件、大小和SHA256，从工程外的独立工作目录离线启动，不以开发机资源路径掩盖缺失。验证本地登录→创建→战斗/升级→装备/披风→任务→保存→退出→重开恢复，含一项铁匠失败与一项满包拒绝。

缺失/损坏资源及存档样本使用隔离目录，错误需有路径与原因；正常退出和验证工具主动终止分别记录。结束检查所有本次启动的引擎、游戏、渲染与辅助进程，不能残留导致用户无法启动。

当前已生成的`target/dist/SoloRxjh-windows-x64.zip`属于旧Rust/P6预览。现有`tools/package_windows.py`和`tools/smoke_windows.ps1`也是旧工具，在P/R阶段替换前不能用于声明Godot版已打包。旧包不包含当前新方案的完整系统。

## 5. 历史源码运行边界

如需只读分析或复现旧版，工具链为Rust1.99.0/Bevy0.17.3，原入口为`cargo run --locked --offline --release`。它启动的是旧实现，不是Godot；本轮文档整理不启动该游戏，不把旧Cargo结果计入目标版测试。
