# 运行与发布

更新日期：2026-11-16。Godot4.7.2/GDScript工程入口、档案菜单和练功场玩法切片已建立。Rust运行时、旧RON、旧打包/烟测脚本已清理；角色成长、完整存档流程和Godot发行包尚未完成。

## 1. Godot开发与校验入口

使用Godot4.7.2标准版，编辑器和导出模板精确匹配。双击工程根目录的`启动游戏.bat`即可运行；它使用`C:\Test\Godot_v4.7.2-stable_win64.exe`，并调用`run.ps1`执行引擎版本检查。启动器使用Windows CRLF换行和ASCII脚本内容，避免`cmd.exe`误拆命令。若引擎文件不存在，窗口会显示预期路径并暂停。

需要从命令行启动或指定其他Godot位置时，在工程根目录执行：

```powershell
godot --version
.\tests\p1_smoke.ps1 -Godot "C:\path\to\Godot_v4.7.2-stable_win64_console.exe"
.\tests\run_all_headless.ps1 -Godot "C:\path\to\Godot_v4.7.2-stable_win64.exe"
.\tests\save_dir_smoke.ps1 -Godot "C:\path\to\Godot_v4.7.2-stable_win64.exe"
.\run.ps1 -Godot "C:\path\to\Godot_v4.7.2-stable_win64.exe"
```

启动脚本要求显式提供实际安装的Godot 4.7.2标准版路径；版本不符时拒绝启动，不自动切换其他版本。烟测执行完整资源导入、结构/路径/类型检查、随机合同及错误路径。普通启动进入本地档案界面，可创建/改名/删除空档案并进入练功场；角色成长、完整任务和存档尚未完成。

`tests/run_all_headless.ps1`串行运行现有规则/集成脚本、隔离档案烟测、`--save-dir`隔离行为、练功场集成、启动参数检查和Godot编辑器导入；只使用headless，并在失败或成功后统一清理本次临时目录、恢复测试环境变量。

应用默认读取`res://assets/config/`和正式导入资源。档案默认写入`%LOCALAPPDATA%/SoloRxjh/profiles/`。启动时可在Godot的`--`之后指定`--save-dir PATH`；PATH覆盖整个存档根目录，程序在其下使用`profiles/`，相对路径按进程当前工作目录解析。未指定时继续使用LOCALAPPDATA默认目录。缺失LOCALAPPDATA、配置、资源或引擎版本时必须明确报错，不切换到其他目录或版本。

## 2. 最终用户启动与操作

目标发行目录包含`SoloRxjh.exe`、Godot资源包、许可、资源清单与本说明；采用嵌入PCK还是外置PCK由导出预设明确，不允许缺包仍显示成功。玩家不需要Godot编辑器、Rust、Blender、数据库或独立后端；单人无需网络，局域网模式需要可达LAN和房主进程。

目标启动流程为本地档案、角色创建/选择和单机江湖；档案、角色及后续系统仍在P2～P6实施，不得以启动成功表示玩法已交付。按键和面板合同见[玩法与功能](02-玩法与功能.md)。

档案目录使用`%LOCALAPPDATA%/SoloRxjh/profiles/`。初版支持列出、校验、创建、改名和删除完整空档案；角色读写、完整历史档案验证及旧存档导入仍未实现。同目录备份恢复代码已加入，Godot 4.7.2隔离故障恢复烟测已通过。

当前仅实现`--save-dir PATH`。`--instance-id`、`--host`、`--port`和`--join`尚未实现，启动时会作为未知参数明确拒绝。目标仍为不同实例使用独立档案根、同一档案禁止双写；端口占用明确失败，不自动换端口。跨机需UDP24572可达，不自动修改防火墙。模式和验收见[19合同](19-局域网组队聊天与多开.md)。

## 3. 导出与包结构

目标预设为`Windows Desktop`，使用4.7.2标准版Windows x64导出模板。预设建立并通过系统测试后执行：

```powershell
godot --headless --path . --export-release "Windows Desktop" target/dist/SoloRxjh-godot-1-windows-x64/SoloRxjh.exe
```

发布工具尚未实现。正式导出须创建全新目录、拒绝覆盖既有版本、生成SHA256资源清单并打包ZIP；包含实际引用的场景、脚本、JSON、模型、字体、音频及许可，排除测试、源工程、用户存档、缓存和本机工具。

Godot引擎许可和随附第三方声明需随发行包保留，字体携带OFL，原创资产来源明确。Godot运行依赖清单按实际引擎与资源生成。

## 4. 包验收与清理

逐项核对目录/ZIP文件、大小和SHA256，从工程外的独立工作目录离线启动，不以开发机资源路径掩盖缺失。验证本地登录→创建→战斗/升级→装备/披风→任务→保存→退出→重开恢复，含一项铁匠失败与一项满包拒绝。

缺失/损坏资源及存档样本使用隔离目录，错误需有路径与原因；正常退出和验证工具主动终止分别记录。结束检查所有本次启动的引擎、游戏、渲染与辅助进程，不能残留导致用户无法启动。

旧Rust预览包及依赖Rust的打包/烟测工具已清理。当前没有正式发行物；P/R阶段须建立Godot发布工具和独立目录验收。

## 6. 历史规则发行保留与恢复

[规则清单合同](contracts/规则清单.v1.json)的historical_retention规定：保留每个已正式交付的完整原发行ZIP及包外SHA256交付记录。记录列明确ZIP文件名/完整包SHA256、从包内实际字节验证的rules_hash及protocol/content/engine版本；两个摘要用途不同。新发行使用全新版本目录，不覆盖、清理旧发行，不以源码或只有哈希的清单替代可运行包。包外记录不加入其所摘要的ZIP，避免自包含循环。

档案备份需要同时保留其依赖的原发行物及交付记录；完整包不写入profile或逐角色复制。恢复旧预留时先核发行来源、ZIP SHA和文件完整性，再由对应规则版本的程序独立枚举资源/核规则哈希，精确匹配pending/source_proof。规则版本还须能完整校验档案版本与写锁/守卫，否则拒绝。

当前程序不动态加载历史脚本/PCK，不自动下载或启动历史exe。规则缺失时显示所需hash/版本并保原档案，匹配发行在独立目录明确启动；未定义跨规则迁移前，历史结果不能直接套入另一规则档案或混连新版房间。已交付规则集没有自动垃圾回收策略，不能因本机暂未发现引用就删除外部备份或其他玩家可能仍依赖的包。上述为P/R实现与验收要求，当前未生成Godot发行包或运行历史恢复。
