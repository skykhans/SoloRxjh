# 英雄武器强化转移采用合同

更新日期：2026-11-14。状态：明确项目设计，未实现，武器成长依赖未闭合。结构化权威为[英雄武器强化转移](contracts/英雄武器强化转移.v1.json)。本合同处理升天四至七式的英雄强化转移；普通晋阶和同阶段提真由32合同独立维护。

## 1. 来源与项目取舍

[五式来源](reference/升天五式强化转移规则.json)和[六式来源](reference/升天六式强化转移规则.json)区分普通装备转移与英雄专属符。普通转移使用两件装备，复制强化和属性石；英雄说明写全部属性保留，而通用FAQ不转合成、觉醒及奇玉，两者边界未公开完整。项目明确将英雄配方单列，不拿普通FAQ覆盖英雄保留规则。

英雄服务项目采用一件原主武器加一个对应符，换出下一阶段同普通/真分支的新武器实例，不要求额外第二件主武器、不要求合成四手。源武器消耗，血统随输出迁移；全部已注册合法成长字段逐项保留，强化不下降。新基础攻击来自目标定义，不能叠加原基础攻击。

官网服务NPC为司空揽杰。项目在泫勃现有刀剑笑提供服务和符商店，是明确本地改编。元宝原价不换算成本地银价：升天4符5000万两、升天5/6符1亿两；各堆99、10克、角色绑定，允许仓储/丢弃，禁止出售/交易/复购，不能直接使用。服务另收0两，100%成功，库存不限，仅向六英雄售卖。上述价格、权限和数量均是项目值。

七式在现有归档五/六式规则及2026改善页中未载明确英雄转移方案。项目新增“英雄七式强化转移符（项目）”，仅用于stage11→12，刀剑笑售价2亿两、170级/rank12六英雄可购，其他堆重/权限同上。每次耗符1、手续费0、必成；不扩大原升天5、6符范围。此为约定七式成长路线的本地设计，名称/价格/配方不能回填成官网事实。

## 2. 配方与输入

47条配方分别为普通24条、真23条。源阶段8→9、9→10、10→11、11→12，最低等级140/150/160/170，角色rank至少9/10/11/12，并且对应adv_09/10/11/12已经交付。原四至六式35条与七式项目12条逐条标识。职业、普通/真分支、源阶段必须精确一致，不跨级、不借此提真。缺少来源的真火龙刀三式不生成8→9真分支配方；其余阶段也不推造。

仅用本人装备背包内未被占用的武器，仓库或两组穿戴须先正常取出/卸下。真实强化接受11～15。附加提升非0或附着临时强化时拒绝本服务；这属于本服务项目范围，不代表正式装备系统可省略15+[n]设计。既有合法绑定/锁保留，不因来源说“不加锁”而解除角色绑定。

须存活、动作空闲、脱战、无挑战，与可用刀剑笑同图且距离不超过2.5米。LAN由房主校验请求者本人资格、钱物和修订，不借队长资格或合并队友材料。

## 3. 提交与失败

预览显示原目标阶段、基础攻击、完整保留字段、符数量、零手续费和源实例将消耗。服务重新核对实例ID、角色/背包/源修订和配方版本；先计算最终布局和重量，再一次提交源消耗、符消耗、新实例和血统/收据。满装备包允许原槽一换一。先验证原库存格数、唯一归属与重量合法；原超重不能因扣符后重量回落而放行。最终携带重量为原重减源武器、减一个符10克、加目标武器；超重整笔拒绝。

未知字段、坏状态或目标不允许原成长值时拒绝，不丢字段、不截断强化、不移除合成/觉醒。取消、过期、条件不足不扣物、不抽随机。重复命令先返回原收据，不能因源已消失再重扣。自动保存失败保留已提交内存结果并标未保存，只重试保存。

只检查角色晋级，不改变角色rank/任务、技能和点数，不发神物之石、经验、历练或武勋；与普通晋阶下降强化和提真材料两套事务分开。

## 4. 验证与剩余依赖

当前静态核对47配方/94身份指针及94正式定义引用，5922组等级/rank/已交付/强化组合（752组符合）。原四至六式35配方的历史96组重量检查见09记录；七式仍按同一恒重/减符10克公式，正式背包行为待运行验证。它们只证明设计引用和条件算术，不是运行时功能测试。

107条主武器基础定义已由[30基础目录](30-英雄主武器基础定义.md)闭合：101新定义和6初始定义引用。47配方均有正式源/目标定义指针，其中真实强化逐级贡献已由[31强化合同](31-英雄主武器强化采用合同.md)采用，[32晋阶/提真](32-英雄主武器晋阶与提真采用合同.md)已补取得链，其他成长schema仍未闭合；无法验证继承状态时必须配置错误，不能从来源行临时造武器或只校验基础定义便激活服务。[33合成/神物之石](33-英雄武器合成与神物之石采用合同.md)已给合成项schema和本地加工；其他成长字段，以及Godot背包/存档/LAN和经济平衡继续待办；本合同不使D1通过。
