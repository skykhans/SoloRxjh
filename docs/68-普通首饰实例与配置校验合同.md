# 68 普通首饰实例与配置校验合同

更新日期：2026-11-15。状态：79款普通首饰单实例结构已采用，未实现。[唯一合同](contracts/普通首饰实例.v1.json)及[Draft 2020-12 schema](contracts/普通首饰实例.schema.json)共同约束读取、新建、加工和参数配置。

## 完整单实例白名单

根实例只包含九字段：`instance_id`、`item_id`、`lineage_id`、`owner_character_id`、`binding`、`revision`、`creation_receipt_id`、`processing_level`、`processing_origin_receipt_id`。全部必需，拒绝额外字段，不通过投影隐藏未知根数据。

位置只由外层容器或装备槽持有，实例不重复保存位置、数量、profile、派生属性或武器/防具成长。精确定义由item_id查66目录，类型与槽位也由定义读取。该白名单是完整单首饰实例形状，不是完整角色、库存或收据日志schema。

先验严格JSON和数字token，再验结构、定义、角色归属、绑定、全库存实例/血统唯一性、槽位、创建及加工来源，最后验外层库存和最终反气功分配。全部ID非空且不能仅空白。合法资格丧失保所有权及成长但不贡献；不能借此跳过坏实例检查。

标准integer会接受数学值为整数的`1.0`，必须额外拒绝小数/指数token、布尔或字符串，不能解码后强转修复。revision为非负精确安全整数，真实加工0～10且满足逐件上限。

## 新建与来源

正式新建分配独立实例/血统，写精确角色绑定及真实创建收据，revision0、加工0、加工来源null。不能用于旧档补字段或按名字猜迁移。

null加工来源仅允许正式创建后未经加工/配置的0级状态。名匠失败降0仍保最近失败收据；普通失败保级也有真实消费和尝试来源。结构上合法的10/null不能通过来源语义检查。

正常加工验证67全部输入、成本、有效概率、唯一随机结果和前状态链。配置修改使用独立`jewelry_processing_configuration`来源，记录旧新等级与修订，不伪造加工成功、符或银消费。后续正常加工保留该配置前缀。

## 参数中心登记

可对选定实际实例直接配置加工0～10，不受日常取得等级或费用拦截；身份、血统、归属、来源和修订由提交管理，不接受方案直接篡改。预览等级贡献及170预算变化，预算不足时明确确认清全部分配并原子应用，取消不变。

配置生成首饰使用新ID及配置创建收据；同时设非零加工时，同事务建立0/null创建锚及配置修改来源，不多发一件。与当前状态完全相同的配置不改实例、修订或日志；正常加工失败保级不能当无操作。

角色独享覆盖存于`character.customization.explicit.ordinary_jewelry_processing`，登记ordinary/master两profile各自的整体成功概率数组和银费数组。每数组恰10项，对应源级0～9；概率为0～10000基点，费用为非负安全整数。只保存存在的覆盖，清除后读取当前67权威值，不保留旧全局备份。

概率0必失败、10000必成功，都不抽整体随机；成功跨阶条件及失败等级规则仍按67。其余概率抽一次。报价绑定配置修订，覆盖变化使旧报价失效；收据保存当时有效参数，不能按后来覆盖重新判历史。未知profile、字段或错长度拒绝。

本轮只登记直接加工等级及四项概率/费用覆盖；贡献曲线、跨阶权重等其他高级字段仍须逐项登记，不能宣称U33配置范围全部完成。
