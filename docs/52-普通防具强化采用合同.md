# 52 普通防具强化采用合同

[结构化合同](contracts/普通防具强化.v1.json)采用[51基础定义](51-普通防具基础定义.md)1219件及[55武勋目录](55-武勋防具基础与成长接入.md)106件的真实强化0～15及15阶材料/概率/费用/失败处理，共1325件，已采用强化防御、生命上限、守护对怪防御、损伤平减和衣服罡气转换五项。武勋件沿同一项目曲线，六个图示覆盖仍仅匹配原普通物品ID；加工须满足当前武勋等全部资格。防具天池神丹另由[61合同](61-普通防具附加提升采用合同.md)采用，其他特殊触发、药品/元素显示及完整根实例/档案schema仍待，服务不开放运行。

6组具名男正衣服的14/15强化防御行直接采用2026图示：普通160/170为550/650、真170为609/717。这些值与基础目录组合后的项目结果不承诺复现复合截图；[50对照](50-防具来源采用审计.md)的105/112差异保留，不逆算或覆盖基础值。真160基础token未决，没有正式物品，不补进此表。

其他组合采用明确项目曲线：JSON逐阶单位×最低转职系数（真件另加1）×部位倍率，衣服倍率2，其他部位1。先精确查6个图示组合，命中只用图示强化行，其他组合只用项目曲线，互斥不叠加。基础和当前强化贡献各加一次，不累计旧阶、不加截图显示总值。仅生效组合法且未失效装备贡献，双护手按各自实际实例；强化防御不改变梅柳真衣服障力平加值。

同6组图示的生命增加和守护对怪防御行现分别采用为 `max_hp_flat` 和 `pve_defense_bonus`。普通160/170的14/15生命620/970、守护303/338；真170的14/15生命660/1010、守护331/368。精确组合取图示行，其余全部合法组合分别查明确项目单位曲线×转职系数（真加1），不乘衣服倍率。生命0～9阶、守护0～6阶明确不提供本项贡献，这些0是项目决定，不把图示未列转为官方0。

生命只加上限，换装/切组/失效时当前生命只按新上限下裁，不回血、不复活；恢复装备不补回已裁掉生命。正常构筑后再应用18的最终上限配置覆盖，不能重复加来源。

守护与宝珠/反气功等独立来源分别进入PvE防御和，再由战斗合同一次计算“普通防御+有效PvE防御”。它不另进普通防御、伤害平减或罡气，不重复抵挡周期/环境/自付伤害。命中结算读取当前生效组和失效部位，来源不符上下文时不永久缓存进普通防御。

损伤减少行采用为 `flat_damage_reduction` 点数，普通精确14/15为70/80，真170精确14/15为80/90。其余合法组合采用JSON项目曲线×转职系数，真加1，不乘衣服倍率；0～6本项明确0。生效且未失效部位逐实例来源相加，在普通/PvE防御及适用罡气之后、现有唯一平减阶段按 `max(0,伤害−总平减)` 处理。不将80当80%，不对周期、环境、自付或状态爆发重复执行。

衣服真实14/15采用10%/20%额外罡气比率，其余部位或0～13本项明确0；其他衣服沿同比率为项目扩展，不声称官网通用公式。转换输入仅该衣服基础普通防御、本合同真实强化防御与53合成owner采用的本实例防御条目和，向下取整一次；不纳入其他装备、角色总防御、最终覆盖、PvE防御或转换结果，进化等其他新来源须另行具名采用后才可加入。原普通防御保留，所得评分只交既有罡气owner，用于直接攻击武功抗性，转换无递归、不是可消耗护盾。

例：普通160男神海战袍真实14，目录基础400+强化550，未合成时项目罡气为95；合成4条防御20时为103，复合截图显示92仍单独保留。10%比率有图示支持，明确输入范围及取整是项目选择，不靠改基础值或拿截图固定罡气量消除差异。衣服失效时同时移除其防御和转换来源，恢复后按当前装备重算。

概率/材料/费用均是独立防具项目方案：前三阶必成，之后90%递降至第15阶10%；逐阶消耗与银费在JSON完整列出，首阶1强化石/100两，末阶15石/1000万两。共享现有 `enhancement_stone` 唯一定义及500两售价，材料适配14职业，不复制新强化石、不借英雄或普通武器的服务资格。满15拒绝，不存在16配方。

计划由刀剑笑执行，源须先放本人装备背包；存活脱战空闲、无挑战/传送/未结算战斗队列，同地图2.5米内，满足全部穿戴资格，原实例及库存完整合法。成功同实例升1；失败同样消费材料和银两但保强化，不毁不降、不清其他合法成长，属于明确项目保护。

报价绑定角色/NPC/会话/源与库存修订/配方版本/材料堆/命令ID，预览完整派生，未决字段不能补0生成可提交报价。房主先查结果收据再重验，在副本扣材料银两、校验最终容量重量，按最终有效概率判定必成（含幸运符补满）不抽样，其余按[统一随机收据绑定](contracts/强化幸运符.v1.json)复制请求角色原随机流抽一次，与消费/实例/修订/收据原子提交。成功失败都去重；同命令异参数拒绝；保存失败只重存同结果，不再次消费或开奖。无效、取消和满级不消费、不抽样。

本合同不含77异常基础值、武勋、门派、初始短衫、武器、首饰、披风或宝珠，不自动完成/提真未完成身份，不用单个强化字段证明整个实例合法。完整成长及派生等依赖闭合后才注册服务。

可选[5%/10%/15%强化幸运符](contracts/强化幸运符.v1.json)沿统一owner处理：每次最多一张，按精确物品分别加500/1000/1500bp、上限10000，不能叠加，原必成档选符拒绝；有效必成不抽随机，其余原单抽。成功失败均扣符，原成本/资格/失败保护不变；报价/命令摘要/收据绑定选符与基础/有效概率，取消/重试不重复消费。现有tier概率及随机标记是未选符的基础值，选符以统一owner计算有效值。此为项目采用，非官网未公开概率。
