# 资源与交互

更新日期：2026-11-13。目标为现代、清晰且有武侠气质的原创3D单机游戏。本文是最终美术与界面合同，程序与功能测试阶段通过后实施；开发几何体、旧版低面数模型和界面原型不计作最终美术完成。

## 1. 视觉方向与质量门槛

风格为清朗的风格化武侠：青绿山林、暖灰石材、深墨屋瓦、玉色主交互和少量铜金强调。角色保持清晰比例、材质和剪影，避免旧版粗糙几何、整屏高饱和发光或大量厚重描边。剧情画面和现代界面属于同一套色彩与字体系统。

最终画面需要清晰的角色面部与发型、可辨认的八类武器、完整服装层次、自然持握、接地阴影、地形层次、场景叙事和有节制的特效。不能只调整色值后宣布质量升级。

## 2. 本地登录、选角与角色创建

| 页面 | 布局与内容 | 交互与质量要求 |
| --- | --- | --- |
| 本地登录 | 原创江湖背景、品牌与版本、本地档案卡片、创建/进入、设置和退出 | 一眼明确是本地游玩；读取、损坏、空档案和不可写状态完整 |
| 角色选择 | 左侧角色列表，中部大幅3D预览，右侧职业/等级/进阶/装备/地图，底部进入与管理 | 切换平滑且身份准确，武器披风与存档一致，无上个角色残留 |
| 角色创建 | 职业卡片、能力定位、中部可旋转预览、姓名和外观选项 | 所选职业有真实说明与动作预览；确认/返回行为明确，不展示未实现选项 |
| 删除确认 | 角色名、职业等级与后果、输入名字确认 | 取消为安全焦点；确认文字与目标一致，不能删除相邻角色 |

角色预览支持转动与缩放，镜头不裁切头部、武器或披风。点击“创建”成功后进入角色列表或新游戏，失败显示具体原因并保留输入。界面上不展示线程、ECS、脚本等实现细节。

## 3. HUD与功能面板

HUD将角色资源放左上、目标状态放上方、任务追踪放右侧、地图放右上、职业快捷栏放底部中央、本地消息放左下；保留中央战斗视野。非交互HUD不截获地面点击。

| 面板 | 必须展示 | 现代交互要求 |
| --- | --- | --- |
| 属性与装备 | 最终值及来源、完整主/辅助装备、宝珠6位、职业/晋级、角色预览 | 当前生效与备用/预览区分；槽位、成长、条件、比较即时更新，不冻结旧11槽 |
| 背包与仓库 | 分类、数量、容量、筛选、排序、物品说明 | 装备实例与堆叠物区分，任务锁和不可卖原因明确 |
| 武学与气功 | 已学、未学、前置、当前/下级效果、花费与剩余点数 | 主动/被动分栏，学习确认、快捷栏绑定和失败反馈完整 |
| 商店 | 商品、价格、数量、总价、余额、容量 | 可调数量；出售预览主线保护；不出现实际不能购买的假商品 |
| 铁匠 | 强化/合成/洗炼/转移/制造、源目标、材料、费用和结果 | 操作前明确成功率与失败后果；结算中防重入，结果后同步实际实例 |
| 披风 | 系列、获取、外观、属性孔、试穿、显隐与穿戴 | 试穿和实际装备区分；预览能看正背面及动作 |
| 任务与门派 | 当前目标/奖励、贡献、晋升、委托和兑换 | 已完成、可交付、不可用原因清晰，追踪入口可操作 |
| 地图与消息 | 图例、等级、路标、筛选、滚动和输入 | 文字可读、阅读位置稳定，输入不触发战斗 |
| 设置与暂停 | 音量、图形、窗口、镜头及保存状态 | 变更实际生效；错误信息有上下文；退出确认完整 |

V25参考原图已明确主装备、辅助装备、宝珠分页、右侧可滚动复购和强化披风MMDD确认，证据见[图示记录](reference/V25图示核对记录.md)。现代界面保留实际系统职责；不能因改版风格漏掉分页，也不以截图可见格数猜列表容量。

## 4. 布局、字体与状态

基准1600×900，覆盖1280×720、1920×1080、2560×1440。使用容器、锚点和可滚动区，不能只把整张1600布局等比压缩。任一目标分辨率下按钮均可达，面板不越界，正文与资源值不重叠。

正文基准20px、HUD17px、辅助信息不小于14px，主要按钮高度至少44px，常用间距8/16/24px，面板内边距24px。使用现有Noto Sans CJK SC及合法字体资源，不能用缺字方框代替中文。

颜色只辅助识别，品质、不可用、危险和选中同时用图标/文字/形状表达。提供默认、悬停、按下、选中、焦点、禁用、加载、空状态和错误状态。动效通常120～220ms，不拖延事务，不遮挡伤害预警。

同一时刻只有一个模态面板；确认页保留明确返回关系。中文输入法组合文字、长姓名、长物品说明、满背包和多条错误消息均必须有布局样本。

## 5. 角色、武器与披风资源

角色源文件保留可编辑模型、骨骼、材质和导出脚本。米制、GLB Y向上、−Z前向；在Godot中核对真实身高、手掌、脚底、武器方向与动画。

- 最终主角模型以清晰轮廓和可近看预览为目标，建议每角色3k～15k三角形；预算需经实际渲染采样确定。
- 各已核对武器类别至少各有可辨认基础模型，高阶系列有真实轮廓/材质变化，不只换名字。
- 衣服、内甲、护手、靴、首饰按显示职责处理；隐藏的内甲仍有属性与说明，不能假装拥有可见模型。
- 官网全部披风系列及实际变体均需建立资源映射，覆盖体型适配、前后轮廓、颜色纹样和次级运动；跑动、攻击、转身时不长时间穿过躯干或武器。具体目录以官网全量核对结果为准，不以六个自拟样本限定范围。
- 待机、走、跑、三段普攻、四武功、闪避、受击、死亡、交互/采集具有完整开始、命中和结束姿态；不同职业按实际武器制作。

旧资源中已发现剑气上身侧弯、穿云刺剑尖朝地；这是已知缺陷，不能迁移后直接标为通过。原动作修复思路是校正转身局部轴、独立腕部控制并检查剑与手掌蒙皮，最终以实际动画过程为准。

## 6. 地图、怪物与特效

千竹岭、云溪谷、寒石古道具有不同植被、地表、建筑、远景和环境色。道路、桥、溪流、工棚、营地、岩壁与挑战场形成可识别路线，碰撞与可见轮廓一致。高阶支路入口有等级与危险提示。

普通、精英与首领不能仅靠名称区分。保留野猪、山狼和凶兽的剪影，新增职业/高阶变体通过体型、护具、颜色和攻击表现区分。危险圈的颜色、范围和时序与实际判定一致。

伤害、治疗、经验、暴击、闪避、任务目标和掉落显示有层级、有效期与同位置排布。技能需要可辨认的起手、轨迹/影响范围和命中反馈；空挥不播放成功命中特效。特效不能遮住敌人预警与地形。

## 7. 音频

主、音乐、音效、UI四条总线；主音量叠乘分项音量。世界音乐与音效随暂停冻结，UI确认可继续；同类短音效最多3并发，退出会话停止世界音源。

原有11份WAV可作基线：2首场景/首领音乐及9个挥剑、命中、起手、受伤、技能、拾取、药品、升级、UI音效。最终增加职业攻击区分、脚步和必要环境声；素材来源与许可逐项记录。没有设备时显示状态，不能因音频失败改变规则。

## 8. 资源清单、许可与验证

现有6个正式GLB、原始Blender文件、11WAV和中文字体保留为迁移资源。来源索引见[assets说明](../assets/README.md)，字体许可见[OFL](../assets/fonts/OFL.txt)，依赖许可见[LICENSES说明](../LICENSES/README.md)。

资源合同检查模型、骨骼、准确动画、材质、音频格式、字体和引用；渲染检查另外覆盖登录、创建、选角、世界、装备/披风、全部武功、怪物、铁匠与地图。每组截图记录分辨率、引擎、渲染后端和实际查看结论。

无窗口测试不等于画面检查，资源存在不等于动画正确。美术阶段必须在程序和功能测试通过后开始，最终改动后重新跑受影响功能回归。桌面物理输入仍停止，人工听验和未执行设备测试继续如实记录。
