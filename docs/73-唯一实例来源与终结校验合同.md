# 73 唯一实例来源与终结校验合同

状态：D1投影设计采用，未实现。参数和语义唯一维护于[来源流JSON](contracts/唯一实例来源流.v1.json)，结构见[schema](contracts/唯一实例来源流.schema.json)。只覆盖[2004已采用实例](contracts/已采用装备实例.v1.json)，不能冒充完整经济事件或档案。

正式结算的instance_flow保存receipt_id、inputs、outputs、retirements。输入引用最后未消费业务输出的收据/索引，并保存实际完整前正文和最新域；输出保存完整实例、操作、来源输入索引、held域及仅新生所需授权。完整历史不是另一份现持库存。纯位置/原样域迁移继续由布局及custody_transfers记录，不重复改业务版本。

| 操作 | 来源与结果 |
| --- | --- |
| create | 无实例前驱，核真实授予/购买/掉落/任务/制作/配置授权，新ID与血统，修订0、创建锚为本结算 |
| revise | 一个前驱，同身份/创建锚，实例修订+1；真实付费失败也记录尝试，拒绝/取消不造流 |
| replace | 一个前驱终结，具名配方新ID保血统，修订0与新创建锚；旧成长凭证沿替换边核验 |
| combine | 宝珠两个不同前驱均终结，输出新ID及独立血统；失败仅终结A，B业务版本保持当前 |
| growth_transfer | 来源索引按目标、源；目标保身份/血统/创建锚并修订+1，源终结，typed元素按48/59 |
| ownership_transfer | 仅71已采用新版武勋首饰，同ID/血统/创建锚，owner转让且修订+1、耐久归0，保加工历史 |

每输入必须恰好同ID存续或明确终结；不可双后继、克隆、遗漏终结、复用已消费ID。替换/合并输出的来源边可引用被终结输入，但旧输入不能继续成为活体。不同具名操作的身份及血统规则不能混用。只终结事件允许没有输出，不在现持表保零值墓碑。

自然remaining_steps递减不增加业务流，因此输入完整前正文允许与上一业务输出的剩余时间不同；必须有同计时代次、同权威世界快照证明，唯一差异限合法递减，不能改层/凭证、刷新或跨代。到期置null须按原owner一次正式revise与修订，不能把坏状态清零当倒计时。完整时钟证据结构仍待。

同一配置命令先创建0初态再修改时，候选内部保两个有序子结算/来源流与真实前驱；整体一次原子保存后发布，不先持久半件物品。角色/库存修订按命令owner一次，实例从0到1。完整事件根及子结算编号仍待，不能临时造收据填历史。

校验顺序为完整结构/token、最后业务输出与最新域、操作身份/修订/具名来源、输入存续终结与全局唯一、费用/材料/RNG和最终布局，再原子发布。实例流与stack_flows、钱、角色/库存修订共同组成真实经济事件；本投影没有单独扣费或发物权。所有已采用实例禁NPC出售，不能借通用域结构新增可售物品。

后续必须实现和验证正常创建/修改/失败、提真、双输入宝珠进化、48/59成长转移、71双人转让、终结与重放，覆盖同一前输出双消费、坏输入索引、缺创建授权、错前域、倒计时与到期、配置组合及跨档案恢复。静态schema样例不等于来源语义、真实存档或LAN故障测试通过；完整经济事件/producer授权/provenance索引/时钟与档案仍待。

新实例身份按instance_identity_v1确定：71规范JSON数组`[settlement_id, output_owner_character_id, new_instance_ordinal]`的UTF8取SHA256小写摘要，分别加`instance:`与`lineage:`前缀。每结算每owner按固定输出顺序只数create/replace/combine新ID输出，从0连续编号；保ID的revise/成长转移/所有权转让不占序号。create/combine取新血统，replace保源血统，不按血统新生数量重编序号。输出索引与新实例序号不等同，客户端不得自行重算另一套顺序。

原权威先分配唯一结算ID并冻结输出顺序和分配结果，存疑保存/重试/重放沿原候选；有序子结算各用不同结算ID。新ID须查全局已分配及已消费历史，新血统亦查全局历史；相同原命令回原结果，新事件碰撞整笔拒绝，不加盐、换序或回收。此法不消费玩法RNG，摘要不证明授权，也不重命名既有旧实例。三个规范向量含中文、控制字符与U+2028，见JSON identity_allocation。

没有专用ID的正式结算由[结算身份owner](contracts/结算身份.v1.json)按原authority_profile_id及档案settlement_next_id持久预留，counter与原事件pending身份/固定计划同档后才能外发。先用完整请求键/摘要去重，不按保存时间/当前余额或客户端可重置计数猜新事件。trade/session/buyback-close专用ID沿原规则，堆流/实例流投影不再次分配结算，实例ID仍从原结算派生。身份片段不代替完整事件日志。

当前业务头和保管域按[现态推导owner](contracts/来源现态推导.v1.json)由完整已提交事件图计算，不持久化第二份head。单结算的堆/实例/银两同收据同索引须按类型区分；实例输出一旦被后继消费便不再活跃，纯域迁移仅改最终域。证明闭包中他角色历史不是本次scope当前实物，不凭单侧档案宣称防双花。

七件旧兼容九字段根已接入，导入仅以真实legacy_import授权保原强化0～3，revision0，不补旧升级历史。创建锚为原导入结算，路径实例ID/专用血统沿旧装备owner；其他新建仍按instance_identity_v1。六件可售不可复购的兼容物通过npc_sale退役，同笔银两收入证明真实售价；不伪装丢弃或生成复购保管。
