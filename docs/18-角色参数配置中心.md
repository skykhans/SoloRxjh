# 角色参数配置中心

更新日期：2026-11-14。来源：用户明确要求“有一个地方能随时更改角色的各项参数，能够任意配置”（U33）。状态：**计划，未实现、未验证**。这是正式单机功能，不是只对开发构建开放的临时命令，也不要求编辑数据库。

## 1. 入口与编辑对象

暂停菜单、角色选择页均提供“角色参数配置”，游戏内快捷键F8进入同一界面。选择当前档案下的具体角色，显示姓名、职业、等级、角色ID及最近保存状态，防止改错角色。可随时打开，离线编辑期间暂停世界；战斗中的提交必须在一致固定步完成，不能直接改正在结算的半帧数据。

新增局域网模式中打开配置面板仅隔离本客户端输入，世界继续；实际应用由房主授权并权威提交，结果同步全部相关客户端。离线仍可直接自由配置。完整规则见[19合同](19-局域网组队聊天与多开.md#5-权威暂停与参数配置)。

一个配置中心按分类展示全部可配置玩法参数，支持字段名/ID搜索、中文说明、单位、当前值、规则计算值、覆盖值和来源。表单与高级批量JSON视图使用同一数据模型，不形成两套规则。用户不用在多个文件或控制台寻找参数。

以上为必需功能范围，字段随系统补全同步增加。未实现系统的字段在开发期标“计划”，发行时不能留下仅展示不生效的控件。正式全局定义由只读配置维护，角色自定义覆盖单独存储，不能改一个角色就悄悄影响其他角色。

## 3. 任意配置与数据一致性

不要求达到游戏等级、支付费用或完成任务才能使用此中心；它就是用户直接配置角色的入口。用户可直接设高等级、转职、资源和最终属性。日常玩法的获取条件不拦截配置操作，但文件类型、引用、整数精度及实例唯一等结构约束仍须满足，否则给出具体错误，不偷偷改成默认值。

编辑等级时，预览将累计经验置为该级起点；可随后精确填写经验。等级与经验同时提供却不一致则要求明确选择，以免两个真实等级字段互相冲突。编辑转职时联动展示对应升天式，角色与武器晋阶仍分开。直接设高等级按14发点合同登记配置跳过区间，不自动补正常气功/升天点；降级保留已处理升级水位，练回旧级不重新领点。需要增减点数时明确编辑并记录配置来源，自有分配与装备有效等级分别预览。

晋级、任务完成和领取奖励分别可编辑：直接设十二转不自动赠送十二次任务奖励；勾选已领奖也不自动补发物品。需要补发时使用明确的“按所选奖励发放”操作并列清单，配置生成记录独立于正常任务领奖事件。用户可分别配置任务状态，但必须显式处理互斥分支，不能默许同时正邪。

最终属性采用“规则计算值→角色覆盖值”顺序，已覆盖字段清楚标识。 最终攻击可用单值同时覆盖上下限，或明确给两个端点；两种表示不能冲突并存，区间须非负整数且下限≤上限，不自动排序修错。清除覆盖恢复当前构筑的攻击区间，不保留旧快照，也不额外加一次武器。覆盖最大生命不自动回复当前生命；若当前值超过新上限，预览联动结果并确认后一次提交，不在读档时静默截断。清除覆盖恢复当前装备/成长计算结果，不恢复一份过期备份值。

角色换职业时列出武器、技能、资源和任务差异，由用户选择具体处理方案后再提交；不可静默删除不兼容物品。物品可转入指定背包/仓库或由用户明确删除，空间不足则事务拒绝。衣饰体型与两组cape资格沿[1155款衣饰资格](contracts/衣饰穿戴资格.v1.json)联验；显式移包/仓处理与身份改变联合校验、同笔提交，不能自动换成另一性别同名款。保留无法生效的能力也必须有明确“配置保留但不生效”状态和说明，不能将未知定义保留下来。

数值范围取本字段类型和明确规则：精确整数0～9007199254740991，概率[0,1]，有限浮点及合法枚举；允许零/负值与否逐字段定义。高级覆盖可放宽正常成长的平衡范围，但不支持NaN、无穷、重复实例ID或不存在的物品/技能定义。若某字段需要越过现有规则范围，先将覆盖语义和校验上限写明，不能运行时悄悄截断。

## 4. 预览、应用与保存

编辑先修改草稿；逐项显示旧值、新值、联动和不兼容项。支持单字段恢复、整类恢复、撤销本次草稿。按“应用并保存”后重新检查角色/档案修订号，整份校验并一次提交，刷新属性、装备表现、HUD及任务界面；失败不留下半套参数。取消关闭不写存档。

配置修订唯一保存为`character.customization.revision`，按[配置修订owner](contracts/角色配置修订.v1.json)从0单调推进；它与覆盖格式版本分开。一次有效配置提交只加1，纯草稿/取消/无变化不分配配置事件或加修订；清空覆盖也不清零历史。报价读取此值，真实配置变更使旧报价失效；已准备交易必须先恢复原决定。

持久字段为`character.customization`，按[四键根](contracts/角色配置根.schema.json)保存format_version、revision、explicit和latest_event_ref；无需覆盖时使用空映射，不复制全部全局参数。物品/任务/资源等直接修改实际持久进度，不能同时另存一份“编辑器角色状态”。最近配置仅保存`latest_event_ref`的authority_profile_id/settlement_id引用，初始null；原committed事件保存提交时间、修改字段和配置来源，不在角色重复抄一份。修订0对应null，正修订须解析同角色原事件及前驱链；展示时间不决定先后，不把参数值伪装成正常升级/掉落。

支持导出角色配置方案、校验后导入方案到明确选定角色。导出不包含用户绝对路径或引擎对象；导入不能覆盖角色ID、档案ID和跨角色实例ID，生成物品使用新ID。先预览差异，再确认应用。格式/版本错误明确拒绝，不能忽略未知字段后导入一半。

保存失败依照05文档保留旧文件与已提交内存，显示未保存；再次尝试保存不重新发物品或奖励。离开有未应用草稿的页面必须提示应用、放弃或返回，不自动提交。

“恢复规则值”只清除覆盖，不删除合法背包或追回正常奖励。“重置角色进度”是不同的危险操作，必须另列明确范围和确认；不能把它藏在恢复默认按钮里。

## 5. 验收与阶段安排

程序阶段P2承接入口、角色选择和草稿/保存；P3～P5随各系统加入完整字段；P6完成全部控件和可读提示。T阶段既测正常成长，也测配置后的场景/保存/角色切换。美术阶段再完成现代配置界面。

计划验证：14职业、各类资源、直接设等级/十二转/七式、装备/宝珠和技能覆盖实际生效；撤销/取消不变；错误字段/不存在引用/超精度整数拒绝；职业切换不丢物；保存失败/重复请求不重复发物；配置方案导出导入、清除覆盖重算及多角色隔离。

正常玩法验收必须使用未配置角色；配置角色的通关不能证明正常经济/成长可达。运行记录标明是否使用配置及修改范围，这不限制用户自由配置，只区分验证证据。当前仅完成设计，尚未实现该入口。

武勋字段character.martial_merit及其0～9007199254740991范围由[六转与单机武勋合同](contracts/第六次升职与单机武勋试练.v1.json)采用，和贡献/名声/普通历练独立。配置修改必须先结束活动并保来源记录，不能调用试练胜利/晋级收据路径；在活动中不允许通过面板改钱、武勋、阶段或敌人状态。


配置rank跨8边界时，三式能力按职业成长owner派生一次，降到8以下移除、恢复时重算，不保存可反复领取余额；当前资源不因此回复。配置晋级不伪造adv_08完成前缀或免费文书。

普通首饰按[68实例与配置合同](68-普通首饰实例与配置校验合同.md)登记：选定实际实例的加工等级0～10及ordinary/master整体概率、费用各10档的四项角色独享稀疏覆盖。直接修改使用独立配置来源，不伪造正常加工成功；无操作不改日志/修订。配置变更使旧报价失效，正常尝试保存当时有效参数。其余高级字段仍须逐项登记，此局部设计不代表U33全部完成。

[69武勋资格](69-武勋阶段与称号资格采用合同.md)登记余额及8/9称号凭证stage、剩余1～155520000步，来源由配置提交生成，不按日常取得门槛拦截。预览资格/预算变化，不伪造认证或续费收据；只改余额不自动发称号。

[70新版武勋首饰](70-新版武勋首饰成长与套装采用合同.md)另登记真实实例加工0～10、耐久0～1000及`merit_jewelry_processing`四项独享概率/最终手续费覆盖。费用覆盖已是最终值，不再乘系列倍率；未覆盖才取67费用乘2/4/6。直接修改与物品生成使用独立配置来源，不能填造所有权/加工/死亡/修理收据，不改普通79款覆盖。来源安全与完整库存校验照常执行。

[71交易准备守卫](71-局域网双人交易与恢复采用合同.md)属于协议一致性记录，不提供直接编辑/清除。当前角色有未决守卫时可看参数，但资源修改、角色删除或切到离线/别房消费原钱物须先取得原房主持久决定并完成应用；不能把配置取消当成交退款。其他角色仍可选择，正常离线无守卫时自由配置规则不变。

[83级经验计时来源](contracts/八十三级正邪洞窟愤怒任务.v1.json)允许独立配置来源创建、编辑剩余步或明确清除，配置四键分支与真实任务五键分支互斥；配置凭证由原配置提交生成，不填造任务ID或完成收据。保原世界时钟/单槽/倍率规则，配置不补发任务奖励，正常任务也不覆盖尚有效的配置源。出尘戒的明确配置创建仍依其独立权限，不会附带本任务经验源。

[吟诗历练源](contracts/七十九级正邪吟诗大会.v1.json)同样允许独立配置来源创建、改余时与清除，原15000倍率及单槽规则保留；与经验源共用[配置计时结构](contracts/配置世界计时来源.schema.json)和[准确字段授权协议](contracts/角色配置修订.v1.json)。同形状不允许跨角色/世界/字段移用凭证，任务授予仍须各自真实完成。

两个计时来源的配置沿[严格原事件](contracts/计时来源配置事件.schema.json)与[事务owner](contracts/角色配置修订.v1.json)：changes只收所选字段的正余时或null，预留不改角色，提交从实际权威步开始计时并各加一次角色/配置修订、库存修订不变。真实来源凭证指原committed结算；未知原配置事件不可凭字符串激活。此局部事务不代表其他配置字段或完整根已完成。

首饰两组覆盖的草稿编辑共用[原编辑协议](contracts/普通首饰实例.v1.json)：缺字段保留、null清除该字段、十项数组整体替换；清最后字段时移除空profile/组。单字段/整类恢复先展开预览实际存在字段，不以通配符清提交前新增覆盖。覆盖存在性本身参与变化判断，即使等于当前规则值。覆盖提交采用[严格三阶段事件](contracts/首饰覆盖配置事件.schema.json)与原配置修订owner的jewelry_override_events；仅改选定稀疏覆盖及角色/配置修订，库存修订不变，预留不发网络结果。完整来源联验与实际保存仍待实现。

武勋余额/称号提交已由[角色配置修订原owner](contracts/角色配置修订.v1.json)的merit_configuration_events登记：changes仅余额、无来源的stage/remaining_steps描述符或null，按三修订与完整来源校验。正常称号转配置属于来源变更；已有配置来源且实际余时/阶段同值才可无变化。所选正称号来源由提交生成，未选称号不刷新。未登记的资格/预算/当前资源复合冲突拒绝提交。
