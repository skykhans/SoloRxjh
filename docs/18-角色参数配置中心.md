# 角色参数配置中心

更新日期：2026-11-13。来源：用户明确要求“有一个地方能随时更改角色的各项参数，能够任意配置”（U33）。状态：**计划，未实现、未验证**。这是正式单机功能，不是只对开发构建开放的临时命令，也不要求编辑数据库。

## 1. 入口与编辑对象

暂停菜单、角色选择页均提供“角色参数配置”，游戏内快捷键F8进入同一界面。选择当前档案下的具体角色，显示姓名、职业、等级、角色ID及最近保存状态，防止改错角色。可随时打开，离线编辑期间暂停世界；战斗中的提交必须在一致固定步完成，不能直接改正在结算的半帧数据。

新增局域网模式中打开配置面板仅隔离本客户端输入，世界继续；实际应用由房主授权并权威提交，结果同步全部相关客户端。离线仍可直接自由配置。完整规则见[19合同](19-局域网组队聊天与多开.md#5-权威暂停与参数配置)。

一个配置中心按分类展示全部可配置玩法参数，支持字段名/ID搜索、中文说明、单位、当前值、规则计算值、覆盖值和来源。表单与高级批量JSON视图使用同一数据模型，不形成两套规则。用户不用在多个文件或控制台寻找参数。

## 2. 可配置范围

| 分类 | 必须提供的编辑能力 |
| --- | --- |
| 身份与外观 | 姓名、14职业选择、派别、允许体型/发型/肤色/配色、披风显隐；职业变更预览不兼容物品和技能 |
| 等级与成长 | 角色等级、累计经验、十二转/升天式、名声、武勋、善恶、普通/升天历练、天机石及各类点数 |
| 基础属性 | 心/气/体/魂，以及项目实际存在的基础生命、内力、体力、攻击、防御、命中、回避、暴击、速度等字段 |
| 最终属性覆盖 | 最终生命/资源上限、攻击/防御、PvE/PvNPC增减伤、攻击/移动速度、技能威力等；覆盖值独立保存，可逐字段清除恢复计算值 |
| 当前资源 | 当前生命/内力/体力、障力、怒气、情绪、护盾/充能等职业资源；不把不同职业资源合成一栏 |
| 技能与气功 | 学习/移除、阶段/等级、分配点、秘籍资格、快捷槽、资源消耗与冷却覆盖；覆盖适用角色全部技能，不限四快捷槽 |
| 装备与成长 | 主辅组、生效组、各槽实际实例、宝珠、强化/合成/觉醒/提真等合法成长字段、披风及外观解锁 |
| 物品与经济 | 银两、堆叠物数量、物品生成/删除、背包/仓库容量、负重上限、交易权限的角色覆盖；唯一实例不以数量堆叠 |
| 任务与组织 | 任务接取/阶段/完成/领奖标记、正邪分支、门派身份/贡献、师徒/关系等实际系统字段 |
| 状态与活动 | 增益/负面效果、剩余时长、冷却、活动轮次/次数、挑战检查点；清除活动需预览票/次数/奖励记录影响 |
| 高级规则覆盖 | 该角色的成长系数、技能参数、费用/概率及获取倍率等正式配置所定义的可覆盖参数；逐字段显式定义类型和适用范围 |

以上为必需功能范围，字段随系统补全同步增加。未实现系统的字段在开发期标“计划”，发行时不能留下仅展示不生效的控件。正式全局定义由只读配置维护，角色自定义覆盖单独存储，不能改一个角色就悄悄影响其他角色。

## 3. 任意配置与数据一致性

不要求达到游戏等级、支付费用或完成任务才能使用此中心；它就是用户直接配置角色的入口。用户可直接设高等级、转职、资源和最终属性。日常玩法的获取条件不拦截配置操作，但文件类型、引用、整数精度及实例唯一等结构约束仍须满足，否则给出具体错误，不偷偷改成默认值。

编辑等级时，预览将累计经验置为该级起点；可随后精确填写经验。等级与经验同时提供却不一致则要求明确选择，以免两个真实等级字段互相冲突。编辑转职时联动展示对应升天式，角色与武器晋阶仍分开。

晋级、任务完成和领取奖励分别可编辑：直接设十二转不自动赠送十二次任务奖励；勾选已领奖也不自动补发物品。需要补发时使用明确的“按所选奖励发放”操作并列清单，配置生成记录独立于正常任务领奖事件。用户可分别配置任务状态，但必须显式处理互斥分支，不能默许同时正邪。

最终属性采用“规则计算值→角色覆盖值”顺序，已覆盖字段清楚标识。覆盖最大生命不自动回复当前生命；若当前值超过新上限，预览联动结果并确认后一次提交，不在读档时静默截断。清除覆盖恢复当前装备/成长计算结果，不恢复一份过期备份值。

角色换职业时列出武器、技能、资源和任务差异，由用户选择具体处理方案后再提交；不可静默删除不兼容物品。物品可转入指定背包/仓库或由用户明确删除，空间不足则事务拒绝。保留无法生效的能力也必须有明确“配置保留但不生效”状态和说明，不能将未知定义保留下来。

数值范围取本字段类型和明确规则：精确整数0～9007199254740991，概率[0,1]，有限浮点及合法枚举；允许零/负值与否逐字段定义。高级覆盖可放宽正常成长的平衡范围，但不支持NaN、无穷、重复实例ID或不存在的物品/技能定义。若某字段需要越过现有规则范围，先将覆盖语义和校验上限写明，不能运行时悄悄截断。

## 4. 预览、应用与保存

编辑先修改草稿；逐项显示旧值、新值、联动和不兼容项。支持单字段恢复、整类恢复、撤销本次草稿。按“应用并保存”后重新检查角色/档案修订号，整份校验并一次提交，刷新属性、装备表现、HUD及任务界面；失败不留下半套参数。取消关闭不写存档。

持久字段为`character.customization`，包含覆盖版本、显式键值及最近配置记录；无需覆盖时使用空映射，不复制全部全局参数。物品/任务/资源等直接修改实际持久进度，不能同时另存一份“编辑器角色状态”。记录保存提交ID、时间、修改字段及配置来源，不把参数值伪装成正常升级/掉落。

支持导出角色配置方案、校验后导入方案到明确选定角色。导出不包含用户绝对路径或引擎对象；导入不能覆盖角色ID、档案ID和跨角色实例ID，生成物品使用新ID。先预览差异，再确认应用。格式/版本错误明确拒绝，不能忽略未知字段后导入一半。

保存失败依照05文档保留旧文件与已提交内存，显示未保存；再次尝试保存不重新发物品或奖励。离开有未应用草稿的页面必须提示应用、放弃或返回，不自动提交。

“恢复规则值”只清除覆盖，不删除合法背包或追回正常奖励。“重置角色进度”是不同的危险操作，必须另列明确范围和确认；不能把它藏在恢复默认按钮里。

## 5. 验收与阶段安排

程序阶段P2承接入口、角色选择和草稿/保存；P3～P5随各系统加入完整字段；P6完成全部控件和可读提示。T阶段既测正常成长，也测配置后的场景/保存/角色切换。美术阶段再完成现代配置界面。

计划验证：14职业、各类资源、直接设等级/十二转/七式、装备/宝珠和技能覆盖实际生效；撤销/取消不变；错误字段/不存在引用/超精度整数拒绝；职业切换不丢物；保存失败/重复请求不重复发物；配置方案导出导入、清除覆盖重算及多角色隔离。

正常玩法验收必须使用未配置角色；配置角色的通关不能证明正常经济/成长可达。运行记录标明是否使用配置及修改范围，这不限制用户自由配置，只区分验证证据。当前仅完成设计，尚未实现该入口。
