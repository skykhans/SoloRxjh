更新日期：2026-11-17。状态：**官网流程已核，单机规则待跨合同审核；未实现**。本合同只定义情侣关系与婚礼边界，不授予物品、旅行或夫妻技能的运行权限。

## 2. 单机适配

项目不使用公网玩家账号；此系统采用玩家角色与明确登记的关系NPC，而非两个玩家角色，也不把普通主线NPC自动当作伴侣。关系NPC必须拥有稳定 `partner_npc_id`、故事身份、性别/礼服适配、交互地图与关系任务映射。该名单当前未建立，是D1冻结阻塞项；实现不得用随机NPC、普通同名NPC或衣饰名称代替名单。

关系只归属当前角色存档，角色之间互相隔离。单机关系以显式剧情/关系任务推进，不使用每日登录、真实时间、在线时长、付费货币或服务器事件。每次关系推进必须引用其权威任务结果收据；重放同一收据不重复升级。具体任务来源、阶段奖励与世界/NPC入口必须在对应任务和世界合同完成绑定后，才可将此关系合同冻结。

## 3. 物品与仪式约束

婚礼厅、券和礼服固定采用以下互斥映射：

| 风格 | 场景 | 入场券 | 玩家/NPC所穿男款与女款 |
| --- | --- | --- | --- |
| 中式 | 龙赡殿 | 42610 | `apparel_59122` / `apparel_59123`（本地映射） |
| 西式 | 圣礼殿 | 42612 | `apparel_42608` / `apparel_42609` |
| 韩式 | 华婚殿 | 42611 | `apparel_42604` / `apparel_42605` |

上表将来源明确的券/厅和现存精确服饰ID分开：西式、华婚衣饰为官网描述映射；中式衣饰与龙赡殿的对应关系为项目采用。玩家角色和关系NPC均须穿着同一风格适配的合法服饰；NPC外观/服装状态由关系NPC外观配置引用，不凭空创建库存实例。

本地关系仪式严格按以下单次状态推进：`dating` → `ring_exchange_ready` → `ceremony_ready` → `consent_pending` → `married`。进入下一状态须同时验证当前角色、指定关系NPC、源任务收据、道具所有权/数量、双方风格适配服饰、场景和仪式修订。任一条件失败不消费道具、不改变关系或场景。

- 关系达到来源要求的4级前，禁止换对戒与预约婚礼。
- 戒指兑换、礼服检查、入厅前校验和仪式开始不提前消费婚礼券；成功进入婚礼厅时一次性消费。入厅前失败不消费；入厅后取消不退券，需重新取得券才能再次进入。
- 玩家必须对本次仪式显式确认。关系NPC的同意必须来自该NPC的正式关系路线/剧情结果，不能由玩家点击代签；拒绝或角色离开即取消本次仪式，回到 `ceremony_ready`。已成功入厅时不返还入场券。
- 玩家确认、NPC同意结果、戒指替换、关系状态和夫妻技能学习来源必须绑定同一仪式ID及修订，在同一权威提交中成功后才进入 `married`。重试返回原结果，禁止重复消费或授予。
- 婚后关系不可经删除物品、换角色、重载或任务重放复制。分离/离婚规则来源未载明；本地版本暂不提供解除婚姻及重复结婚。

戒指身份与旅行权限分离。`couple_ring`/`marriage_ring` 当前仅由[便携传送与修炼限制](contracts/便携传送与修炼限制.v1.json)保留身份，不能作为已经定义完毕的可用商品。婚姻合同不得启用戒指传送、期限、属性或商店出售；补齐取得、目标、冷却、地图限制及原子消费后才可激活。

## 4. 夫妻技能

官网明确的技能为“探花血雨”：威力与内功消耗分别等于已学习最高等级武功的威力与消耗。目标类型、距离、冷却、动画、学习方式及职业适配未载明；下列执行细则均为本地项目采用，不宣称为官网规则。

### 本地技能选择与施放规则

- 候选来自当前角色合法已学的直接攻击武功：六职业/乐师格斗普通武功、英雄普通武功中 `kind=attack` 的定义、升天武功中 `role=attack` 的定义，以及旧剑技中有直接伤害定义的招式。排除治疗、障力恢复、增益、控制、纯被动和非直接伤害能力；不能仅因技能有数值或名称含“攻击”就纳入。
- 候选须通过原技能owner的职业、路线、等级、晋级、技能阶段及取得来源验证。只考虑当前已学阶段，不把可学习但未学、不可用或来源缺失的技能当作候选。武器资格按该候选原定义验证；不因婚姻跳过原职业/武器限制。
- “最高等级”采用可复算的技能等级键：普通武功取其定义 `minimum_level`；英雄普通武功取当前阶段 `minimum_level + phase - 1`；升天武功取 `source_learning_level + phase - 1`；旧剑技取 `minimum_character_level + learned_rank - 1`。升天技能阶段必须来自其已学状态，旧剑技等级必须来自经来源验证的实际等级记录。缺值、公式/阶段引用无法解析时拒绝施放，不用角色等级代填。
- 按技能等级键降序选择。等级相同时按当前阶段/段位降序、该阶段每次命中的原始平量威力降序、`ability_id` UTF-8 字节升序依次决胜。不得按数组顺序、快捷栏顺序、当前目标或冷却状态改变排序。没有合法攻击候选时，技能不可施放；不得回退为普攻、免费攻击或常数威力。
- 成功接纳时，从同一个选中候选及其唯一owner读取平量威力与内力成本；普通武功按其原 `minimum_level`、`action_profile` 公式计算，阶段技能按其已采用阶段行读取，旧剑技按其原等级/段位公式读取。不可把来源值复制为另一份静态表。若内力不足，拒绝本次施放且不改选次高技能。
- 探花血雨复用所选攻击的合法武器要求、动作时序和直接攻击几何，但本技能每次仅选择一个合法敌对目标；不继承该来源的连段、额外目标、职业专属附加效果、状态效果或攻击触发。命中沿[战斗命中与减伤合同](contracts/战斗命中与减伤.v1.json)唯一直接武功命中路径结算，保留通用攻击/减伤来源，不复制二次攻击力或技能触发。
- 本地采用独立冷却600世界步（60Hz下10秒），归入角色主动技能冷却owner；仅成功接纳并支付时启动。接纳失败不扣内力、不启动冷却、不创建动作；接纳后取消、被打断或未命中均不退款、不清冷却。暂停与离线按对应时钟owner冻结。
- 夫妻技能唯一通过婚姻提交授予，能力ID、选择算法版本、授予仪式ID和来源修订随角色技能学习来源保存。施放接纳冻结所选 `ability_id`、阶段/段位、技能等级键、威力、内力成本、原定义修订及动作参数；施放期间配置或角色状态变化不能重选或改写该根。
- 当前技能学习根仅允许普通主动、升天主动、旧剑技三个严格owner；独立主动冷却键也只允许现有823个学习身份。夫妻技能尚无正式 `ability_id`、学习状态/schema分支、婚姻授予收据映射、独立冷却身份登记或直接攻击选择schema登记。联审必须为其增加唯一婚姻授予owner，并同步技能根/实例schema、婚姻提交来源、冷却注册和直接攻击选择；普通训练事件不得学习、升级、移除或伪造此能力。未完成所有严格白名单同步前，不得写入角色根或冷却表。

以上规则覆盖14个角色职业；升天攻击按具体 `role=attack` 筛选，不能将整份升天目录误作攻击表。选择规则和数值来源已形成项目设计，夫妻技能仍未实现。实际施放还须通过完整角色/战斗状态、冷却来源和共同保存协议的跨合同校验；完成前婚姻仪式不得授予可施放技能。项目采用的600步独立冷却只有在上述身份/schema及触发来源注册完成后才生效，当前不属于现行823项冷却配置。

## 5. 保存、恢复与失败

最终角色/档案schema须持久保存唯一关系NPC身份、关系阶段、已验证的阶段收据、婚姻状态、婚礼风格、戒指转换来源、技能学习来源及修订。仪式中的 `consent_pending` 和事务ID必须能在崩溃恢复时判定原提交结果；不得恢复为可再次扣券/再授技能的未决副本。完整角色根和共同提交协议当前未完成，本节不授权运行时写档。

以下情况整笔拒绝且状态不变：伴侣ID不在正式名单；关系等级不足；券/礼服/厅风格不匹配；券不属于当前角色或数量不足；礼服只在背包而未穿戴；玩家确认或NPC同意结果不是本仪式当前修订；超距、场景迁移、死亡、战斗或角色切换；重复请求指向不同摘要；提交/保存失败无法证明原结果。

## 6. 验收落点

在G25增加婚礼专用用例：三种风格逐一正确匹配；所有券×场景及券×礼服错配均拒绝；爱情度3/4边界；未穿戴、错误性别/礼服、券交易或伪造来源拒绝；玩家拒绝、NPC不同意、NPC同意过期、角色离开、入厅前后取消与券退还边界；婚礼成功仅发生一次戒指替换和技能授予；重放、保存失败、断线恢复、角色切换不能重复提交；婚后衣饰资格不变；修炼房与禁戒地图仍由便携移动合同拒绝传送。技能效果另按G04/G09验证，不以合同静态检查替代运行结果。

## 7. 冻结阻塞项

1. 建立关系NPC正式名单、个体身份/故事来源、性别及礼服适配和地图服务锚。
2. 定义可追溯的关系阶段任务及每阶段唯一收据；不能把“爱情度4级”硬编码为无来源数字进度。
3. 玩家/关系NPC体型与三类婚礼礼服的资源绑定、展示和穿戴适配待A阶段验证。
4. 将本节技能选择规则与14职业攻击配置、完整角色技能状态、战斗动作/命中/冷却owner联审；正式登记婚姻授予ID、独立学习owner与冷却/直接攻击白名单后，实现运行时接纳与保存恢复。
5. 将婚戒、对戒取得/替换与服务效果和角色根/任务/NPC/物品提交跨合同审查。
